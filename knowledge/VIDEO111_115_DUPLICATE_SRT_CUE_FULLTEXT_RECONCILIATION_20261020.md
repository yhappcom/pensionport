## 2. 공개 전문과 본문 오차의 정확한 원인

양쪽 자막을 `\s+` 제거 방식으로 UTF-8 정규화하여 비교. 2026-10-20 동일 YouTube URL에서 한국어 로케일(KR/ko) 공개 전사를 재취득하고, 공개 본문을 유지하면서 원본 SRT 측 **인접 cue와 내용이 완전히 동일한 중복 cue만 비교 시 일시적으로 생략**했다. 실제 SRT 파일의 cue를 수정하거나 삭제하지 않았다.

**원본 중복 cue 위치 (모두 인접 cue와 문자 그대로 동일):**

- **#111 `zDcF_zPTSYE`:** `cue441`은 `00:14:32,720 --> 00:14:33,959`에 `>> 주식 모으기.`, `cue442`는 `00:14:33,399 --> 00:14:36,000`에 같은 `>> 주식 모으기.`가 다시 저장되어 있다. 공개 전사는 이 중 두 번째 `cue442`에 해당하는 **공백제거 8자**를 생략한다. 이 중복 cue 한 건만 생략하면 공개 전문의 길이와 해시 모두 정확히 일치.
- **#115 `Yr2yMyGLsX0`:** `cue6` `00:00:10,000 --> 00:00:14,410`과 `cue7` `00:00:11,320 --> 00:00:16,430`에 `>> 박꼬미 TV.`가 중복. 공개 전사는 두 번째 `cue7`에 해당하는 **8자**를 생략.
- **#115 `Yr2yMyGLsX0`:** `cue87` `00:02:37,160 --> 00:02:38,040`과 `cue88` `00:02:37,680 --> 00:02:39,480`에 `>> 안 하죠.`가 중복. 공개 전사는 두 번째 `cue88`에 해당하는 **6자**를 생략. 총 **8+6=14자** 차이를 전부 설명.

이것은 공개 전사가 겹친 중복된 표시용 구간을 하나로 취급한 **본문 표기 방식 차이**이며, 상기 중복 제거 전에는 원본/공개 원문 해시가 불일치하는 2026-10-18 관측도 사실로서 보존한다. 원본 파일 자체를 오류로 단정하거나 손상된 파일로 폐기하지 않는다. 음성에서 같은 표현을 실제 두 번 말했는지는 **오디오 독립검사 전까지 결론 내리지 않는다**.

### 코드 재현 방식

~~~python
from pathlib import Path
import re, hashlib

def normalize_cues(cues, exclude):
    # cues: [(cue_index, time_range, text), ...] parsed from SRT
    body = "".join(text for cue_index, time_range, text in cues if cue_index not in exclude)
    return re.sub(r"\s+", "", body)
~~~
