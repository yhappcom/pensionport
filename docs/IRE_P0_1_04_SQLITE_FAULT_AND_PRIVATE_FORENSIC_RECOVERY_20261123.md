## 실제 발견 및 수정 결함

V128은 동일 부모 재발행을 멱등 처리하지만 기존 V243은 `parent_count` 증가 1만 성공으로 인정해 안전한 재실행도 실패했다. V166 E4 봉인기도 같은 부모의 재실행에서 동일 SQLite 내용의 새 sidecar를 재작성할 수 있었다. V243은 **정식 외부 이전 봉인 PIN이 존재하고 재검증된 상태에서만** 동일 부모의 행 0건 증가 재실행을 허용하도록 고쳤다. V166은 동일 자식별 승인 지문·동일 체크포인트·동일 전체 DB가 확인될 때 **기존 봉인 바이트와 PIN을 그대로 유지**한다.

GitHub 합성 시험 중 `unittest.TestCase.run` 충돌과 변조 V123 결과의 HOLD/예외 오판을 확인하여 시험 결함 자체를 수정했다. 확인된 공식 반응인 `HOLD_E4_PRIMARY_EVIDENCE`도 **기존 인증 데이터 불변, 신규 저장 0건**이어야만 시험을 통과한다.

- 동일 부모 재실행: 기존 소유자가 별도로 유지한 E4 seal PIN을 다시 제공하면 지식·이벤트·부모 행 **증가 0**, HMAC sidecar 바이트 동일. PIN이 없다면 재실행을 거부한다. 변경된 ChatGPT 판정은 E4 HOLD, 봉인 기록 불변.

## 실패 후 복구의 실제 범위

**중요 예외:** V128 SQLite가 자식 전체를 원자적으로 커밋한 직후 E4 sidecar의 `os.replace` 이전 프로세스가 중단되면 **실제 부모 데이터 1건·지식 3건이 물리적으로 남는 경우가 있다**. 이는 *부분 자식 발행*이 아니라 *전체 부모 미봉인 검역 대상*으로, E4 인증·지식 조회·임의 재발행은 모두 차단된다. **자동 운영체제 수준 롤백을 달성했다고 주장하지 않는다.**

새 `E4SealedKnowledgeStore.quarantine_unsealed_parent`는 별도 **비공개 디렉터리 모드 0700**, forensic 파일 **0600**, **기존 DB 행 SHA 외부 PIN**을 요구한다. 독립적인 전체 SQLite forensic 복사 및 논리 지문 재검사 후에만 활성 DB의 3개 지식 테이블을 **BEGIN IMMEDIATE 하나의 트랜잭션으로 비운다**. 이미 봉인됐거나 인용 SHA가 다르거나 백업을 보존할 수 없다면 복구를 거부한다. 비운 직후 2차 오류가 생겨도 검역본을 삭제하지 않는다. 복구 후 새 체크포인트 PIN을 사용한 정상 전체 재심사·발행을 합성 검증했다.

따라서 P0-1-04 통과 의미는 **원자적 자식·부모 저장과 비인가 지식 발행 차단, 명시적 검역 복구가 실제 SQLite로 재현됨**이다. 무인 장애 복구, 불변 운영 권한 체계, 외부 owner PIN 실제 보관까지 자동 검증했다는 뜻이 아니다. 이 운영 잔여위험은 P0-1-05의 E1 최종 정책 판정에 보존한다.
