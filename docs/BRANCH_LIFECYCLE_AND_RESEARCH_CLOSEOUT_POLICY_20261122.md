# IRE 브랜치·연구 완료·자료 보존 운영 기준 (2026-11-22)

**적용:** `yhappcom/pensionport`의 전체 투자 연구 및 E1~E5 개발. **유효 시작:** 2026-11-22. 기존 산발적인 브랜치 생성 관례보다 본 기준이 우선한다. 정책의 기본 목적은 **연구 단위를 브랜치 개수와 동일시하지 않고, 모든 연구의 원본·검토·승인·정정을 추적 가능하게 남기는 것**이다.

## A. 반드시 지킬 브랜치 운영 규칙

1. `main`은 현행 레거시 코드/등록부의 보존 기준이고, **본 통합 과정에서는 어떠한 쓰기·병합·force push도 금지**한다.
2. 통합 작업은 기존 `audit/full-repository-snapshot-20261122` 브랜치를 재사용한다. **별도 신규 연구 브랜치 생성은 원칙적으로 금지**하며, 매 영상·매 턴·매 E1 수정·매 시험에 새 브랜치를 만들지 않는다. 사용자 별도 승인 없는 신규 브랜치 예외도 금지한다.
3. 개발 코드·합성 시험·공개 가능한 근거 매니페스트는 통합 브랜치 내 버전별 디렉터리/작업 상태 ID로 관리한다. **브랜치는 실행 상태 저장소가 아니다.** 원본 영상별 체크포인트는 비공개 저장소에 두고 공개 GitHub에는 비식별 SHA/상태/연계 키만 저장한다.
4. 운영 목표 브랜치 수는 **`main` + 단일 통합 브랜치 = 2개**이다. 긴급 보안 수정 등의 예외는 사용자의 명시적 승인, 합병 대상/예상 폐기일/담당자/백업 SHA를 사전 문서화하고 14일 이내 종료한다.
5. 개발·연구 시작 전 GitHub 전체 브랜치/열린 PR 수를 확인해 기준 초과 시 신규 브랜치 생성 대신 기존 통합 브랜치에서 처리한다. **메인으로 PR을 보내거나 자동 병합하지 않는다.** 통합 브랜치가 운영 가능한 검증본이라는 주장도 금지한다.
6. 기존 PR/브랜치의 종료는 `branch_name`, 원래 HEAD, 대상 통합 HEAD, Git 조상 포함 검증(`merge-base --is-ancestor`), 단독 변경사항 목록, 검증 상태, 연계 연구 영수증을 남긴 후에만 허용한다. **Git 이력 병합은 코드의 의미/성능 합격이 아니다.** 분기별 구현을 활성 엔진으로 채택하려면 별도 diff-review·충돌해결·회귀·실물 승인 검증이 필요하다.
7. 통합 브랜치에서 E1~E5·한 편 전체 영상·중단복구 시험을 같은 기준 SHA로 실행하고, 실패 시 원인/OPEN 수/재현 입력을 보고한다. 각 버전 이름을 단독 운영 브랜치명으로 사용하지 않는다.

## B. 연구 작업을 위한 브랜치를 분리했을 때의 필수 종료 절차

연구용 임시 브랜치 예외가 승인돼 생성됐다면, **종료하기 전 반드시 연구자료를 검증·정리**한다. 브랜치 이름만 닫거나 최신 코드만 복사하는 것은 완료가 아니다.

### B1. 원본과 연구 계보 고정
- 영상 ID/원본 SRT SHA-256/자막 개수/시간·인용 범위/모델 입력 버전/기준 Git HEAD/기존 누적 지식 HEAD를 저장한다.
- 개인 원본 SRT·민감한 검토 메모·포트폴리오·상세 투자 사례는 공개 Git에 두지 않는다. 개인 자료는 접근 통제된 비공개 공간에 저장하고, 공개 Git에는 최소한의 해시·보관 위치 식별자만 기록한다. 임시 ZIP 한 개만 남기고 종료하지 않는다.
- 이전 연구 원장·보류사항·OPEN을 삭제하지 않고 `previous_receipt_sha256`, `new_receipt_sha256`, `research_status`로 연결한다.

### B2. 필수 실제 사용자 2턴
- **1턴:** 실제 영상 원본·기존 지식·원자/문맥을 검토해 변경 불가능한 1차 연구 체크포인트와 미해결 내역을 만든다.
- **2턴:** **새로운 별도 사용자 메시지**에서 ChatGPT가 원본과 1턴 고정 산출물을 다시 읽고, 원자별 화자/입장/조건/예외/숫자/시점과 공식근거·관계 판정을 검증한다.
- 2개 함수 호출, 2개 파이썬 프로세스 또는 한 사용자 턴 내부의 재실행은 정식 2턴으로 계산하지 않는다. 수동 메시지 ref는 플랫폼 발급 암호학적 서명으로 승격시키지 않는다.
- 2턴 결과는 승인/수정/격리/보류를 구분하고 `source_sha256`와 원자 ID/수정 전후 SHA/검토 근거에 묶는다. 불확정·검토 불일치가 남아 있으면 승인되지 않으며, 종료 보고서에 이전한다.

### B3. 최종 연구 산출물·지식 반영
- 원자/화자/조건/예외/수치/인용/근거 최신성/기존 지식 동치·충돌·개정/시점/OPEN·격리 목록을 자식·부모 구조와 함께 기록한다.
- 정식 `V123` ChatGPT 검토·`E4` 적법 승인·`E5` 원자적 통합을 실제 통과한 지식만 승인 원장에 넣는다. 구간 13개 중 하나라도 미승인이면 원래 승인되지 않은 원자를 임시 출판하지 않는다.
- E1 구조적 패킷 PASS, E2 의미 정확도, E3 최종 결정, E4 법적 근거, E5 발행을 서로 다른 수치로 보고한다. CI PASS/해시 PASS를 금융 사실 승인으로 전환하지 않는다.
- 기존 누적 지식의 변경은 원자 관계(`SAME/SUPPORTS/EXTENDS/CONFLICTS/SUPERSEDED/DISTINCT/OPEN`)와 교체 이유를 보존하며 기존 지식 임의 삭제·합병 금지.

### B4. 브랜치 종료 영수증 (필수 필드)
`research_id`, `source_video_ids`, `base_commit_sha`, `branch_final_sha`, `integration_commit_sha`, `first_turn_checkpoint_sha`, `second_user_turn_reference_and_authentication_level`, `second_turn_review_sha`, `V6_child_receipts`, `V123_verdicts`, `E4_authorization_status`, `E5_knowledge_head_and_publications`, `open_docket_and_owner`, `private_evidence_location`, `CI_run_urls`, `real_source_replay_result`, `research_summary_path`, `merge_status`, `closeout_at`, `deletion_safe`.

**허용되는 연구 종료 상태:** `APPROVED_AND_INTEGRATED`, `CLOSED_WITH_EXPLICIT_HOLD_TRANSFER`, `QUARANTINED`, `CANCELLED_WITH_ARCHIVE`. 보류 상태 이월 없이 `DONE` 표시 금지. 소스 자료가 외부에서 재현 불가하면 `VERIFICATION_NOT_REPRODUCIBLE`로 명시한다.

### B5. 브랜치 정리 완료 조건
1. 해당 HEAD와 고유 변경(직접 변경 파일/연구 검토/단위 테스트/근거)이 통합 이력 또는 불변 보관본에 남아 있는지 확인.
2. 임시·검증용 중복 파일 중에서 누가 정식 운영 버전이고 어느 것이 역사 자료인지 분류. 삭제 대신 우선 archive/orphan 분류.
3. 미결 OPEN을 중앙 연구 큐/검토 원장에 이관하고 브랜치별 마지막 연구 영수증을 등록.
4. 열린 PR의 의견/실패/의사결정 요약을 연구 영수증에 연결하고, 통합 완료 뒤 PR을 명시적으로 `SUPERSEDED` 또는 `CLOSED_WITH_HOLD` 처리.
5. `main`, 현재 통합, 사용자 지정 보호 브랜치는 삭제 금지. 나머지는 대상 HEAD에 조상 포함 확인 및 브랜치 SHA 사전 일치가 모두 참일 때만 정리.
6. 삭제 전후 전체 브랜치 수·SHA·열린 PR·미해결 연구 건수를 비교해 누락이나 의도치 않은 승인/코드 변경이 없음을 검사.

## C. 고정된 승인/변경/운영 게이트
- **문서 우선:** 기능 변경 전에 원인 → 최소 수정 계약 → 위험 → 합격 및 부정시험 기준을 `docs/` 또는 검증 보고서에 먼저 고정한다.
- **코드 수정은 한 번의 기준 브랜치에서:** 과거 다른 브랜치에서 수선한 코드가 있으면 파일 SHA·업스트림 설계와 영향도를 비교하여 정식 CI로 들어오기 전 충돌 재검토. 여러 실험 브랜치를 계속 파생하지 않는다.
- **안전 우선:** `main`/동결 V6/개인 원본 수정 금지; `main` merge 금지; E3/E4 없는 E5 PASS 금지; 사용자 2턴 대체 금지.
- **기준 문서 하나:** 현재 운영 상태는 중앙 `docs/BRANCH_CONSOLIDATION_20261122.md` + E1~E5 상태 매트릭스에 단 하나의 근거 SHA로 기록한다. 과거 문서의 PASS는 그 당시 시험 범위에만 유효하다.
- **CI 지표:** 현재 코드 전 범위 테스트, E1~E5 종단간 양성·음성 시험, 매체 원본 검문, 재실행/중복/중단/변조, 2턴 경계의 명확한 상태, 일별 브랜치 수/OPEN 정책 위반을 확인.

## D. 예외/통제 불가능 범위
- 공개 저장소에서 개인 SRT·비공개 단일 지식 원본 전체를 자동 공개·복사하지 않는다.
- Git 브랜치 통합은 파일 경로 수준의 코드·금융 의미 검증이 아니다. 특히 11개의 분기 끝점에서 서로 충돌하는 구현은 기본 루트에 무조건 활성화하지 않는다.
- GitHub 계정/플랫폼이 제공하지 않는 호스트 서명이나 외부 원본 권한을 위조하지 않는다.
- **저장소의 791개 영상 로스터와 실제 승인 완료 영상 수를 혼동하지 않는다.**
