# ChatGPT 기반 2턴 투자 연구 엔진 — 실행 가능성 중심 재설계

기준 2026-11-24 · 기존 통합 검증 브랜치만 사용 · 현재 P0-2-05 HOLD.
**설계 변경 방향과 운영 시험을 확정한다. 기존 독립 정확도 합격 기준 또는 PASS를 임의 변경하지 않는다.** 운영 시험 결과가 확인되기 전에는 정식 체크리스트의 완료 기준 변경/후속 단계 착수를 허용하지 않는다.

## 1. 현재 설계의 원인 진단

현재 60개 순차 체크리스트, 마스터 계획, 원문/원자/골드 검토, E3 V123, E4 V240, E5 V128, V126 자문 경로를 기능별로 대조했다. 이번 검토는 현행 저장소 2,559개 트리 항목을 열거하고 핵심 운영 문서 및 관련 실행 코드를 직접 확인한 것이지 모든 파일의 새로운 전수 의미 감사가 아니다.

- **실행과 성능 인증의 혼동:** P0-2-05에서 실제 2턴 연구 절차인 E3에 도달하기도 전에, 별도 격리 세션 2개와 사전 등록 중립 호스트 서명이 필요한 독립 인증을 요구한다. 현재 채팅은 해당 호스트 키나 격리된 리뷰 세션을 생성할 수 없다. 이를 위조하거나 더 많은 서명 검사를 만드는 것은 해결이 아니다.
- **정답 자료 오염/과적합:** 이미 여러 차례 검토한 ETF 원본에서 코드·정답·원자를 함께 수정하고 다시 시험하면 개발 사례의 회귀에는 유용하지만 새로운 영상에 대한 일반화 증거가 아니다. 독립 골드 0개인데 소프트웨어 검사는 926개가 되었고 순차 체크리스트는 16/60에 머물렀다.
- **완료 기준과 원자 수의 혼동:** 원문 250 cue, baseline 68개, 수정안 70개, source-first 71개는 다른 분모다. 실제 shadow70에서 175개 cue는 UNRESOLVED, 70개 모두 speaker UNKNOWN/stance UNRESOLVED다. 모든 인용이 원문과 맞는 것만으로 의미 완결성은 증명되지 않는다.
- **역사 상태의 고정:** scripts/ire_p0_2_05_gold_readiness_gate.py 및 root_cause_gate.py 등은 당시의 HOLD를 현재 진행 원장과 결합해 확인한다. 향후 실제 운영 시험이 성공하고 완료 기준을 개정할 경우, 이 역사 증빙 검사와 현재 운영 진행 판단을 분리하여 과거 HOLD를 영구 실행 조건으로 오인하지 않게 해야 한다. 이번에는 역사 증빙 및 기존 승인 차단을 그대로 둔다.
- **책임 경계:** 별도 모델 API 호출·격리된 대화 자동 생성·호스트 인증은 현재 대화에서 이용할 수 없다. ChatGPT의 실제 사용자 메시지에 기반한 의미 재검토와 공식 자료 검색은 가능하다. GitHub/SQLite는 결정론적 저장·회귀·복구를 담당한다. 개인 포트폴리오 연결은 최종 단계다.

## 2. 두 개의 검증 경로로 분리

| 구분 | A. 운영 실증(현재 실행) | B. 독립 정확도 인증(별도 상태) |
|---|---|---|
| 목적 | 한 편의 실제 연구·검토·근거·지식통합 경로가 정상 동작하는지 | 고정 예측 대비 실제 독립 정답셋 정확도 |
| 방법 | 실제 사용자 TURN1 동결 → 다음 실제 사용자 TURN2 원문 재검토; 내부 교차검토 및 근거 판정 | 독립된 검토 자료와 출처·블라인딩 증거; 기존 prereg 및 matcher 보존 |
| 지표 | 원문 100% 처분, 원자 전체 대응, 고위험 사용제한, 내부 reference 비교(완전한 경우에만 수치) | 정밀도 ≥95%, 재현율 ≥98%, 고위험 FN=0 |
| 신뢰 표시 | SAME_CHAT_INTERNAL_REVIEW, host attestation 없으면 false | independent_gold_verified=true는 실제 독립 근거가 있을 때만 |
| 현재 상태 | TURN1_FROZEN_AWAIT_ACTUAL_NEXT_USER_MESSAGE | HOLD_NO_INDEPENDENT_GOLD; 수치 null |
| 승인 | 실증은 E3/E4/E5 정식 승인 아님. 현행 순차 게이트 유지 | 인증 불가를 합격으로 치환하지 않음 |

**운영 실증을 시작하기 위해 두 별도 서명 세션을 요구하지 않는다.** 실제 독립 인증의 기준은 완화하지 않는다. 운영 실증 성공 시, 원래 P0-2-05 독립 정확도 항목을 삭제하거나 몰래 PASS 처리하는 대신, 운영 준비성과 독립 벤치마크의 관계에 관한 정식 체크리스트 변경안을 시험 증거와 함께 명확히 기록한다. 실제 운영에 독립 인증을 선행 필수로 유지할지에 대한 정책 결정 전에는 다음 항목이 차단된다. 현재는 같은 P0-2-05 범위 내 운영 실증만 허용한다.

## 3. 고정 운영 절차 및 완료 기준

**TURN1:** 실제 사용자 요청을 받고 원본 전체를 읽는다. 기준 영상 ID, 원본 bytes/SHA, 기존 연구 HEAD, 원문 선행 주장/문맥/숫자/조건/예외/OPEN, 예상 원자, 비교 기준 및 평가 범위를 동결한다. 후보를 임의 정답으로 가정하지 않는다. 원본 전용 검토 입력은 후보 자료와 파일 단위로 구분한다. 동일 채팅 내 이전 후보 노출을 명시한다.

**TURN2:** 다음 실제 사용자 요청에서 원문 전체부터 재검토한다. 원문 자막별 claim/context/nonclaim/OPEN을 처분하고 근거를 기록한다. 원문 기준 내부 참조를 확정하기 전 후보와의 세부 대응을 수행하지 않는다. 이후 모든 후보·참조의 KEEP/REVISE/QUARANTINE/HOLD 및 일대일 대응·불일치를 기록한다. 부분 일치는 FP와 FN으로 각각 계산하고 단순 주제 유사성을 TP로 계산하지 않는다. 미확정 화자 신원/음성/화면을 임의 확정하지 않는다. 과거 영상 발언과 최신 공식 금융 규정을 구별한다.

고정 완료 기준:
1. 전체 source cue 100% 처분·출처 대조, 처리 대상 누락 0. 모든 후보와 참조 원자의 처분 기록. 미확정은 명시적 HOLD/QUARANTINE이며 단순히 삭제해 분모에서 빼지 않는다.
2. 원문 의미·유형·화자 역할/입장·부정/반박·조건·예외·숫자/단위·시점·가상/실제의 모든 의미 항목을 확인한다. 고위험 불일치 미해결 항목은 승인 제외; 완전한 참조가 없으면 지표 null.
3. 기존 정량 목표(95/98/0)를 **완결된 내부 참조 대비 진단 목표**로도 사용한다. 내부 수치는 독립 정확도와 별도 필드에 기록하고 현재 ETF를 새 holdout이라고 주장하지 않는다. 원본68 및 수정안70의 지표를 각각 표시하고 수정 후 점수로 원래 점수를 대체하지 않는다.
4. E3/E4/E5 정식 처리에서는 기존 typed V123·V240·V128 단일 관문 재사용, 모든 자식 처분·공식 원문 근거·승인권한·원자적 저장/재개봉/중복실행 검증을 요구한다. 운영 시험 자체는 권한·출판 승인 아님.
5. 기존 P1-1의 미노출 5편 실증은 평가 전 영상 ID, 코드 SHA, 기준, 후보 SHA와 내부 reference 동결 순서를 사전 등록한다. 평가용 영상으로 평가 버전을 수정하지 않는다. 실패는 그대로 보고한 후 결함군 전체 원인 수정; 다음 버전은 별도 미사용 영상에서 재평가한다. 13 child와 250 cue는 이 개발 영상의 분모이지 모든 영상의 고정 개수가 아니다.

**금지:** 개별 반례가 나올 때마다 정답 변경/기준 변경을 반복하여 같은 평가를 통과, 불필요한 신규 서명·호스트 검증 장치/상태 전용 시험 추가, 합성 CI를 연구 품질로 승격, 기존 원본/후보 덮어쓰기, 신규 브랜치/main 수정. 예외는 명확한 데이터 손상·실제 재현되는 범용 실행 결함의 수정이다.

## 4. 실제 적용 — 첫 턴의 연구·검토 범위 동결

실제 ETF 원본 250개를 다시 읽고 15개 연속 의미 구간으로 업무를 정리했다. V228 원본68·shadow70·기존 source-first71의 SHA 및 원문 인용/자막 해시를 재검사하여 0개 불일치를 확인했다. 기존 후보 71개는 이미 본 적 있는 미승인 초안이므로 독립 정답이 아니다. 현재 70개 원자 전체는 화자·입장 미확정, 175개 cue는 UNRESOLVED. 앞선 고위험 10개는 여전히 독립 판정 OPEN이다.

비공개 운영 시험 묶음: P205_CHAT_OPERATIONAL_TRIAL_TURN1_FROZEN_20261124.zip, Library libfile_6612fa0c6a8c81919192d5ca16c4d0c5, SHA-256 41cf6757c8cd2bb02f13e6d60e712a05cf8c7de1a1b2525159d0a895a397c02a.
묶음에는 실제 원본·250개 원본 전용 검토 입력·15개 구간의 의미 읽기/업무 목록·기존 68/70/71 자료·위험 10건·고정 평가 계약이 포함된다. 공개 Git에는 SHA-only receipt와 설계만 보관한다. 별도 호스트 서명 없음, source-first 독립 격리 아님, 독립 지표 null.
