# V6-000 — Deterministic Research Kernel Redesign (implementation baseline)

**Date:** 2026-11-08. **Status:** ACCEPTED FOR ISOLATED IMPLEMENTATION; NOT RELEASED.
**Canonical input:** `yhappcom/pensionport`, dev branch `feat/ire-v5-vertical-slice-20261103`, HEAD `f753ba57a1afabaa849f3eeca88170938c0b51f6` verified at design start.
**Protected:** `main`, approved master 116, P4 29, V1–V5 histories, and owner-private ZIP/SRT. No migration or remote changes authorized by this ADR.

## Context and motivating failures

The V5 JSON-per-event kernel replays and mutates in-memory model, evidence, relation and terminal state. Isolated P0 cycles exposed rollback-after-write, exception-before-write, crash publication, stale read and forged/reused second-pass proof risks. Passing CI for a V5 commit does **not** certify an unmerged patch or independent semantic truth. We avoid another cross-version patch chain by introducing an isolated V6 kernel.

## Non-negotiable design decisions

1. **Transactional owner of facts.** Persist transitions under one SQLite `BEGIN IMMEDIATE` transaction: event row, derived-state digest, sequence/head compare-and-swap. Failed transaction leaves no new persisted transition. Never mutate an authoritative in-memory state first.
2. **Pure reducer.** `state_machine.reduce_event()` has no I/O, model calls or global side effects. Replay from durable events is the only projection authority. Event bodies use strict canonical JSON: no floats/NaN, no variable timestamps in event digests, no Python-specific object types.
3. **Optimistic client head.** Every command has `expected_head`; stale commands fail. Idempotent retry with the same `command_id`, payload and expected head returns the original event receipt, even after a newer event exists. Reusing the id with different input fails.
4. **Concurrency.** Each operation creates its own SQLite connection. WAL+FULL and a local filesystem only; SQLite serializes writers. Readers use one SQLite snapshot, replay and validate the complete chain and never reuse stale cached state. Full physical disk durability still depends on OS/storage guarantees.
5. **Revision-anchored review.** Every model submission, including A→B→A, creates a new `revision_event_sha256`. Review proposals must reference the exact current revision. Old reviews are never silently valid for a later revision.
6. **No self-certification.** V6-1 only supports `SCOPE_DECLARED`, `MODEL_RECORDED` and `REVIEW_PROPOSED`. SOURCE_VERIFIED, REVIEW_VERIFIED, FORMAL_APPROVAL, REPORT_CLOSED and ENGINE_GO are not accepted event types. `issue_terminal_receipt()` intentionally fails until independent verifier modules are implemented and proven on real source/evidence.
7. **Private provenance.** V6-1 records hashes and unverified source pointers but does not claim to read/verify a private SRT. The source byte+cue validator, private content-addressed store and immutable owner-pinned inventory are V6-2 prerequisites. A hash generated by an attacker is not proof of provenance.
8. **History and source separation.** Historical V1–V5 data are read-only until a versioned, separately tested migration bridge exists. Private review or transcript data in this database must remain in a private directory, never committed to the public repository.
9. **Approval separation.** CI success, source-byte provenance, semantic recall from independent gold, financial evidence applicability, and personal decision authorization are distinct verdicts and never imply one another.
10. **Host boundary.** Python cannot invoke another ChatGPT conversation or independent reviewer. Host decisions are untrusted commands and do not grant approval. Offline scripts cannot independently certify investment truth.

## Data schema (V6-1)

- `scopes`: unique scope, video ID, source digest, manifest digest, current sequence, current event hash.
- `events`: `(scope_id, sequence)` and `(scope_id, command_id)` unique; canonical event JSON; command digest; previous and current event hashes; derived state digest.
- Protected invariant: `replay(events) == declared_head_and_state_digest` at every operation.
- **Storage limitation:** a malicious party with full database write authority can rewrite an entire hash chain. V6-3 must anchor checkpoints outside this trust boundary. The current chain detects ordinary modification and incomplete writes, not adversarial full re-signing.

## Attack-to-invariant matrix

| V5 class | V6 contract | Enforced test |
|---|---|---|
| Ghost model/seal on failed disk write | INV-01/02/03 | exception and `os._exit()` before COMMIT; reopened DB unchanged |
| Stale memcache/ABA proof | INV-04/06/07 | new snapshot for each read; model revision event identity |
| Concurrent same-HEAD submit | INV-02/04/05 | two processes, one commit / one explicit conflict |
| Duplicate command after client response loss | INV-05 | replay same event and refusal of divergent payload |
| Deleted/modified event | INV-03/09 | replay rejects broken head and event/state hashes |
| False source/finance/engine approval | INV-09/11 | all progress marked unverified; terminal issuer disabled |
| Cross-cohort duplicate video or source | INV-08 | globally unique video and source within private DB |
| Incomplete Git checkout | release contract | strict prepush returns BLOCKED before any remote write |

## Next milestones (not implemented by this package)

- **V6-3** Reproducible `ProofVerifier` with review input persisted, revision/chain/policy binding, independent external checkpoint anchors, safe migration of legacy proof with `LEGACY_UNVERIFIABLE` default.
- **V6-4** Official evidence and master-116 read-only reconciliation; scoped, temporally correct financial fact gate.
- **V6-5** `TerminalReceiptAuthority` executes all required validators under the same checked snapshot, refuses stale/false/absent proofs, writes an immutable terminal event in one transaction.
- **V6-6** Pre-registered independent blind goldset: overall and high-risk TP/FP/FN, precision/recall, strict alignment; no independent gold means `UNMEASURABLE`.
- **V6-7** Full same-checkout mandatory six prepush commands exit0, V6 regression suite, private real-original replay, exact-SHA CI, canary comparison against V5, protected-path diff check.

## Non-goals and current limitations

V6-1 is a deliberately narrow software foundation, NOT an SRT analyzer, ChatGPT agent, complete research pipeline, CI-certified V6 release or financial advice engine. Full-chain replay on every command is correctness-first but O(n) per command and must be benchmarked before corpus scale. Network filesystems are unsupported; remote multi-host clients must call a single authoritative service or be rejected. Power loss recovery and independent provenance remain unproved until separately tested.
