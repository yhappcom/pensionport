# IRE V6-004 — Owner-inventory pin and finance-candidate proof chain

**Status:** isolated executable prototype; production source/semantic validity and strict prepush **NOT VERIFIED**. Implemented against the offline V6-1–3 artifact based on the development-tree Git SHA `f753ba57a1afabaa849f3eeca88170938c0b51f6` (2026-11-08 KST). All changes are additive within `ire/v6`, preserving V5, `main`, 116 approved items, and 29 P4 educational nodes.

## Exact authority and truth boundaries

- **External owner pin**: `trust.verify_owner_inventory` checks the *exact raw SRT*, its manifest, cue census, source/video ID and a **canonical full inventory** against a SHA-256 value fixed *independently* before submission. Registry schema `IRE_V6_OWNER_INVENTORY_V1` contains unique `(video_id, source_sha256, manifest_sha256, cue_census_sha256)` entries. Duplicate source bytes under alternate video IDs are rejected within that particular inventory. This **does not** globally prevent the same video being scheduled in two separate cohort DBs. That requires a single global ownership registry/transaction in a subsequent phase.
- **Pin provenance**: the API accepts an expected digest supplied by the host. It cannot itself establish that this digest was genuinely committed by the owner. An attacker who can replace both registry and expected SHA can pass byte-level checks. The adversarial fixture explicitly reproduces this limitation. Owner identity, authenticated signing and an independently held immutable ledger checkpoint remain **OPEN**. Never label this as owner authentication.
- **Pinned source events**: `TransactionStore.attest_owner_inventory` atomically records only the pin match and source digests after prior real-byte source attestation, without storing raw SRT in the event. It cannot be forged through the generic event-submit API; retries are historical/idempotent and new digests under the same command ID are refused.
- **Financial evidence**: `finance.audit_official_candidate` verifies *captured document bytes* against an independently chosen SHA-256, declared HTTPS URL/issuer, literal quote presence, retrieval/publication/effective dates and applicability at `as_of`. A URL string, captured quote, or date does **not** establish issuer authenticity, semantic entailment or legal validity. No network retrieval is performed. Future-effective and expired documents remain `DATE_NOT_APPLICABLE`, and the engine never auto-approves either.
- **Prior knowledge**: `finance.audit_prior_relation` verifies a pinned metadata baseline, unique prior IDs and a proposed relation target. This checks **membership**, not source bytes of approved items or the meaning of SAME/CONFLICT/SUPERSEDED. Current tests use **three synthetic entries**, not the owner's 116 actual approved records. Relation status remains PENDING.
- **Atomic candidate event**: `submit_finance_candidate` obtains a write transaction, verifies current source pin and current structural proof, replays the actual model/review anchors, checks the official document + prior baseline, matches candidate claim ID to the current model and records `FINANCE_CANDIDATE_RECORDED`. The derived state tracks current-revision **candidate record count only**, not true facts. If the model goes A→B→A, prior finance proof becomes historical and does not regain current status.
- **Independent read replay**: `snapshot_with_finance_candidate` replays the entire SQLite event chain, original SRT bytes, pinned inventory, model+proof, captured official document and pinned baseline within one consistent read snapshot. New bytes or proposals that no longer match the saved audit are refused. A valid historical result is not proof that the snapshot is *still latest* at any later time; compare with `is_current` before use.

## Storage and migration

V6 state and DB schema change to `IRE_V6_STATE_V3` and SQLite `PRAGMA user_version=3`. Older V6 v1/v2 database objects cannot be silently opened with the new reducer because re-derived event state hashes change. A separate evidence-preserving migration protocol and test must be approved before legacy conversion; none is performed. All event payloads contain digests, minimal issuer URL/metadata and pending statuses, no verbatim SRT or captured official document text. The SQLite private data directory still requires owner-only permissions.

## Failure model and acceptance

The test suite injects corrupt SRT bytes and manifests, independently pinned source replacement, repeated video-ID/content in a full inventory, official document quote/digest/date/URL errors, forged relationship approval and mismatched baseline, revision A→B→A, duplicate request ID, SQLite pre-COMMIT failure, bytewise replay drift, poisoned event chain and unauthorized terminal receipt. The relation enum unhashable-value `TypeError` was found by malformed-input mutation, reproduced RED, then fixed with an exact str check and typed `InvalidInput`; do not count it as a real-source finance error.
