# V5 Run Failed 재발 방지 및 금융자문 승인 기준 (2026-11-04)

## 1. 실제 Run Failed 근본 원인

개발 브랜치 `feat/ire-v5-vertical-slice-20261103`의 최신 30개 GitHub Actions 실행을 대조했다.
이 중 성공 18, 실패 12는 동일한 **중간 커밋 4개 × push/PR 중복 실행 3개**로 반복 표시되었다.
최신 `fb8c62c83ff3264c951a7a4ae27369a94a5c3e73`에서는
V5 standalone, cleanroom(push), cleanroom(PR) 3개가 모두 통과했다.

실제 실패 사례는 다음과 같았다.

1. `365d83b...`: IRP 정부발표일(2026-10-29)을 '연구 검증일'(2026-11-04)과 혼동하여 검증기에서 차단.
2. `faa7733...`: 한국어 자연어의 정확한 부분 문자열을 테스트에 요구하여 의미가 같은 다른 표현을 실패 처리.
3. `4c3f111...`: '세액공제 금액'과 '환급액'이 별개라는 설명은 있었으나 특정 단어만 인식하는 문자열 검증기가 실패.
4. `10605c1...`: 부적절한 연금 인출 주장 오류 주입 테스트가 '전용 위험 검증'보다 먼저 일반 텍스트 길이 검증에 걸림.
5. 각 실패 커밋마다 cleanroom push/PR + standalone push가 동시에 동작해 **한 문제를 세 건의 Run Failed로 노출**.

위 문제는 최신 커밋에서 해결되었지만, 새 기능을 중간 단계별 커밋하고 CI를 사전 검증기처럼 사용했던 **개발 프로세스**도 구조적으로 개선해야 한다.

## 2. 실제 적용한 재발 방지

1. `ire/v5/preflight.py`를 추가. 개발자 컴퓨터와 V5 GitHub Actions에서 똑같은
   **10개 검증 단계**를 실행한다. 원본영상 ID, 기존 주장, 미승인 승격, 가상 질의,
   20+5 지식, 신규 5편, 관계 통합, 외부 공식자료, 교육용 중복 제거, 전체 회귀테스트가 포함된다.
   어느 단계든 실패하면 즉시 nonzero로 종료하고 오류명을 표시한다.
2. `ire-v5-transaction-core.yml`은 더 이상 10개 명령을 별도 장소에 복제하지 않고
   **단일 V5 preflight 명령**만 실행한다. 모든 기존 검증과 테스트는 유지한다.
3. `ire-cleanroom-gate.yml`의 push 트리거에서 **V5 개발 브랜치만 제외**했다.
   해당 브랜치의 push 검사는 standalone이 맡는다. **PR cleanroom 검사는 계속 유지**한다.
4. 새 커밋이 들어오면 검사가 완료되지 않은 이전 커밋의 run은
   concurrency 그룹으로 취소한다. 취소 ≠ 성공, 최신 커밋은 반드시 전수검사를 마쳐야 한다.
5. `ire/v5/tests/test_preflight.py`가 필수 검증단계 누락·순서 변경 및
   테스트 실패 무시 방식이 없음을 감시한다.
6. 기존 실패한 GitHub Actions 이력은 사라지지 않는다. 신규 커밋의 실제 오류도
   **안전하게 실패해야** 한다. 'Run Failed가 절대로 0건'을 보장하거나 검사를 끄지 않는다.

### 개발 후 커밋 이전 필수 수행

프로젝트 루트에서 다음을 실행해 정상 종료(`PREFLIGHT_ALL_PASS`)를 확인한 뒤
V5 개발 브랜치에 통합한다.

```bash
python -m pip install 'cryptography==46.0.4'
python -m ire.v5.preflight --root .
```

검증계획만 확인하려면 `python -m ire.v5.preflight --list`.

새로운 기능을 ChatGPT GitHub API로 직접 작성하는 경우 로컬 Git 훅이
자동으로 실행되지 않으므로, *커밋 전에 동일한 테스트가 가능한 작업 환경*에서
preflight를 실행해야 한다. 직접 코드가 바뀌지 않은 보고서 변경도 계약 형식
검사를 통과해야 한다. GitHub 단독으로 '검증 전 커밋'을 막는 기능은 아니므로
브랜치 보호/PR 필수 통과도 병행하는 것이 적합하다.

## 3. 미검증 44개와 승인 가능성: 엄격한 단계 분리

현재 53개 신규 잠정 주장 가운데 **서로 다른 9개 주장**에 대해
10개 공식자료 대조 평가를 수행했다. 나머지 **44개는 여전히 미검증**이다.
5개 근거 충족 평가를 중복 제거하면 **범위가 제한된 일반 교육 지식은 4개**.
단, 이는 외부인 블라인드 승인 4건이 아니다.

44개 전체의 자료 확인이 끝나더라도 자동 자문 승인이 되는 것은 아니다.

| 구분 | 승인 가능 조건 | 현재 판정 |
| --- | --- | --- |
| 일반 금융교육용 사실 | 원본 cue·정확한 요약·금융기관 근거·시행일·예외·경고 | 4개 교육 항목 후보, 비블라인드 |
| 개인 재무 의사결정 지원 | 미노출 문제의 독립 정답·근거 충실도·거부율/위험한 확답 검증, 고객별 필수조건 처리 | NO-GO |
| 유료 1:1 개인별 투자자문 영업 | 해당 서비스가 투자자문업에 해당하는지 검토하고, 관련 금융위 등록·전문인력·금융소비자보호 의무 등 충족 | 별도 법적 검토·등록 여부 미확인 |

**완료 기준은 '44개를 무조건 승인한다'가 아니라 44개 전부를
EDUCATIONAL_SUPPORTED / CONDITIONAL / OUTDATED / CONTRADICTORY /
UNSUPPORTED / NON_FINANCIAL 등으로 판정하고 불확실성을 공개하는 것**이다.
일부 주장은 올바르게 보류·폐기되어야 한다.

정식 자문지원 GO에는 최소한 아래를 충족해야 한다.

- 원본 53개 주장과 별도 미노출 원본을 이용해 금융 주장 누락률 측정.
- 법규 시행일과 개정안 분리, 실제 금융기관의 최신 상품·세금 규칙 대조.
- ChatGPT가 만든 정답을 그대로 자체 평가하는 방식이 아닌 독립 블라인드 정답/오류 판정.
- ISA·IRP·연금세제 등 각 영역의 조건누락·수치오류·미확정 단정에 대한 별도 정량 검증.
- 개인 정보가 빠진 질의에서 확정적인 투자 매수·비중·절세금액을 안내하지 않도록 게이트.
- 고객별 자문 상품화 시 규제 적용 여부·등록/자격/적합성 관리에 대한 법률 준수 판단.

## 4. 정확한 결론

- **내부 교육용 지식베이스의 단계별 승인 가능성:** 있음. 일부 44개는 검증 뒤 교육용으로 승격할 수 있음.
- **실제 개인별 투자자문을 자동 실행하는 엔진의 승인 가능성:** 44건 검증만으로는 부족. 독립 QA·안전성·법적 운영조건을 추가 충족해야 함.
- **GitHub 'Run Failed' 제거:** 최신 실패 원인을 해결하고 중복 실행과 중간 커밋 노출을 축소할 수 있지만, 신기능 결함이 생길 때 오류 검사가 실패해야 하므로 무실패를 영구 보장할 수 없음.
