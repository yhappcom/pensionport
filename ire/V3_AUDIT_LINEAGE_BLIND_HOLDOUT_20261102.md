# IRE V3 — 유효 주장 감사 영수증·블라인드 패킷 재검사 (2026-11-02)

## 원인과 기존 검증 허점

V3 품질 보고서는 원본 패킷 SHA와 원자 주장 인용 SHA를 기록했지만,
**불변 정정 원장이 반영된 유효 창별 응답 전체**의 SHA는 보고서에 연결되지
않았다. 동일한 원본 인용과 위험 개수를 유지하면서 주장 표현·조건·계산
구조만 바꾼 경우 과거 보고서와 동일한 해시가 생성될 가능성이 있었다.
따라서 원본 SHA·경고 개수만 확인하는 보고서는 최신 의미 판정의 증거가 아니다.

## 개선 적용

1. `v3_claim_quality.audit_claim_quality`는 실제 응답을 읽은 각 창에 대해
   `effective_answer_sha256`을 계산한다. 요청된 영상/문맥/패킷/유효 응답의
   순서 있는 배열을 `audited_effective_answer_set_sha256`으로 봉인한다.
   개별 의미 위험에도 본인 및 선행 조건 주장에 해당하는 응답 SHA를 기록한다.
2. `save_private_quality_report`는 **현재 ChatBatchQueue 입력을 필수로** 받아
   감사 전체를 다시 계산한다. 보고서 자체 해시가 맞더라도 현재 유효
   응답과 일치하지 않으면 신규 파일을 만들지 않고 실패한다. 이전 호출자는
   `save_private_quality_report(report, private_dir, queue)`로 수정해야 한다.
3. `v3_blind_protocol.audit_blind_review_plan`은 기존 비공개 블라인드 패킷을
   원본 SRT 패킷과 다시 대조하여 원문/시간/문맥/영상 ID·해시, 중복 태스크,
   태스크 및 계획의 무결성, **선택 후 저장된 모델 답변 존재 여부**를 검사한다.
   `python -m ire.v3_blind_protocol verify --private-manifest MANIFEST
   --private-plan PLAN`으로 구조 확인 가능. 이전 대화에서 모델이 원본을
   읽었는지와 독립 인간 평가자 신원·판정은 이 검사로 증명되지 않는다.

  승인으로 보지 않는다. 연구 통합과 자문 게이트는 계속 차단한다.

## 한계

SHA-256만으로 외부 저자의 신원/서명, 원문 발행기관 진위, 상담 사례의
경제적 인과관계, 독립 골드 평가, 동시 프로세스가 파일 사이를 변경하는
상황까지 인증하는 것은 아니다. 현재 코드는 현재 대화에서 출처 연계
검사·구조적으로 재현 가능한 경고 원장을 만드는 도구다. 외부 모델
API 호출 없음, 기존 main 및 v001/v002/v003 비공개 답변 미변경.

## 저장된 과거 감사 결과의 현재성 재검사

- `python -m ire.v3_claim_quality verify --private-manifest MANIFEST
  --private-report PREVIOUS_REPORT`는 현재 유효 창별 응답을 다시 분석하여
  `CURRENT`(종료 코드 0)와 `STALE_AFTER_SOURCE_OR_ANSWER_CHANGE`(종료 코드 2)를
  구분한다. 자기 해시 자체가 무효인 입력은 실패로 차단한다.
- 위험 건수가 동일해도 주장 내용 또는 정정 계보가 달라지면 오래된 보고서는
  최신 판정 자료가 아니다. 이전 보고서를 삭제하거나 최신 것으로 덮어쓰지 않는다.
- 이 검사는 리서치 상태 최신성만 판단하며, 금융 사실 인증과 독립 심사는
  여전히 수행하지 않는다.
