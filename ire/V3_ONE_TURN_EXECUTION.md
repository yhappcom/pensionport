# IRE V3 — 한 번의 사용자 요청에서 가능한 최대한 완주하는 실행 계약

**2026-11-02 — ChatGPT 현재 대화, 외부 LLM API 사용 안 함.**

## 목표와 기술적 경계

사용자가 `#1~#5 분석 및 기존 지식과 통합`이라고 한 번 지시하면,
ChatGPT가 사용자에게 문맥별 JSON이나 매 차례 `진행`을 요청하지 않고
원문 확보 → 해석 → 검증 → 잠정 지식 통합 → 공식 근거 확인 및 자문 품질 판정을
**같은 대화 응답 안에서 연속 수행하도록 시도**한다.

새 `v3_one_turn.py`는 **모델을 호출하지 않는다.**
이미 현재 ChatGPT가 원문을 보고 작성한 금융 의미 답변이 충분하면,
단일 CLI 호출에서 모든 응답을 검증·접수하고, 완료된 전체 배치만 기존
새 IRE 지식 원장에 통합한다. 문맥 답변이 없으면 채워 넣거나 요약에서
금융 주장을 임의 생성하지 않고, 첫 미처리 문맥과 미충족된 품질 게이트를
명확히 반환한다.

이는 **준비된 적법한 답변을 한 번에 처리하는 기능**이지 ChatGPT를
Python이 별도 API 없이 무한 호출할 수 있게 하는 기능이 아니다.
구체적인 모든 영상 분량의 *한 턴 완주를 무조건 보장하지 않는다.*
데이터가 커질수록 현재 대화의 문맥·시간·도구 제약에 의해 중단될 수 있다.
다만 완료되지 않은 분석을 성공으로 표시하거나 기존 연구를 덮어쓰지 않는다.

## 한 번 실행 (실제 입력과 저장 위치는 ChatGPT가 내부 관리)

```bash
python -m ire.v3_one_turn execute \
  --private-manifest /private/batch.json \
  --private-answers /private/chatgpt_cited_answer_bundle.json \
  --private-knowledge-dir /private/ire_kb \
  --private-audit-dir /private/ire_audits \
  --max-packets 12 --max-chars 60000 \
  --private-result /private/one_turn_completion_receipt.json
```

답변이 아직 없더라도 같은 명령에서 `--private-answers`를 생략하면
검증된 현재 체크포인트를 기반으로 정확한 첫 미처리 창/차단 사유를 표시한다.
해당 다음 창의 **원문만** 기존 `v3_orchestrator next`로 읽은 뒤
ChatGPT가 의미 분석을 작성할 수 있다.

### 답변 묶음 계약

```json
{
  "schema": "IRE_V3_ONE_TURN_ANSWERS_V1",
  "batch_fingerprint": "원본과 세션을 검증해 출력된 실제 SHA-256",
  "answers": [
    {
      "video_id": "확인된 원본 영상 ID",
      "submission": {
        "schema": "IRE_CHAT_WINDOW_ANSWER_V1",
        "session_id": "실제 session ID",
        "window_id": "W00001",
        "packet_sha256": "실제 원본 패킷 SHA-256",
        "claims": [],
        "cue_dispositions": []
      }
    }
  ]
}
```

**주의:** 빈 `claims`/`cue_dispositions`는 형식 설명용이며 실제 문맥 분석
완료 예시가 아니다. 모든 primary cue는 실원문 인용을 가진 원자 주장과
연결하거나, 정당한 비주장/미해결 상태를 각각 기록해야 한다.
숫자, 조건, 단위, 금융상품 추측으로 빈칸을 자동 보충하지 않는다.

## 코드가 수행하는 일

1. 원본 SRT와 영상 ID·전체 cue 수·SHA-256·현재 불변 체크포인트 검증.
2. 파일 전체를 먼저 사전 검사: 답변 중복, 다른 영상 패킷, 누락 인용,
   부적절한 고위험 비주장 처리, 기존 원문 답변의 임의 변경 차단.
3. 원본 순서대로 최대 12개, 최대 60,000자의 **연속된** 패킷을 선택해
   각각에 해당하는 이미 검증된 답변을 제출. 현재 창이 비어 있으면
   뒤의 준비된 답변으로 건너뛰지 않음.
4. 응답을 한 개씩 저장하지 않고 가능한 경우 묶음으로 제출하여
   채팅 호스트의 도구 호출 수를 줄임. 중단되면 저장된 체크포인트로
   재개할 수 있고, 동일한 답변 묶음은 기존 **기본 답변과 일치할 때만**
   재사용할 수 있음. 정정 답변은 `v3_orchestrator correct`로 별도 기록.
5. 모든 창이 제출돼도 교차 문맥 인과관계·미확정 세율 단위·고위험
   누락이 하나라도 있으면 잠정 지식 스냅샷 갱신 거절.
6. 모든 문맥과 중요 의미 품질 게이트를 통과하고 저장 디렉터리를
   지정한 경우에만 기존 V2의 **누적 연구 스냅샷**을 추가함.
7. P0~P2 완료 게이트를 **같은 명령에서** 점검하고 미충족된 공식
   근거·독립 평가·투자자 적합성·자문 평가 사유를 반환.

## 성공 코드의 의미

- 종료코드 `0`: 모든 원본문맥 답변의 검증·저장 및 **잠정 연구 지식
  스냅샷** 생성 완료. 이는 공식 금융 사실/자문 승인과는 다름.
- 종료코드 `2`: 일부 답변 누락, 분석 품질 미해결 또는 지식 스냅샷
  미생성. 다음 작업 위치를 반환하고 이전 체크포인트는 보존함.
- 종료코드 `3`: 원본·묶음·인용·해시·입력 형식 등 검증 실패.
  오류 텍스트에 비공개 원문을 표시하지 않음.

반환된 `one_turn_full_source_completion_achieved`는 **창 전수 접수**,
`one_turn_research_snapshot_written`은 **잠정 연구원장 갱신**을 뜻한다.
두 값 모두 공식 금융 사실/독립 검토자의 정확도 인증이나 자동 자문 승인으로
해석할 수 없다. 원본 입력이 아직 미완료면 `remaining_windows`와
`next_video_id`/`next_window_id`를 통해 단일 채팅 중 계속 연구할 수 있다.

## 검증 원칙

원본 ZIP 및 분석 답변은 개인 비공개 공간만 사용한다. GitHub에는 엔진
코드, 테스트, 형식 계약, 원문이 없는 비식별 통계만 저장한다.
기존 `main`, V2 연구, 원본 SRT 및 v001~v003 체크포인트는 수정하지 않는다.
원자 주장 골드 정답/법적 효력은 별도 독립 검토자·공식 원문으로 심사한다.

## 원본 중복 제거형 패킷 계획 — 한 턴 문맥 부담 축소

추가 명령:

```bash
python -m ire.v3_one_turn prepare \
  --private-manifest /private/batch.json \
  --private-packets-file /private/one_turn_source_compact.json \
  --compact --max-packets 12 --max-chars 60000
```

원본 SRT의 각 cue 텍스트와 시간정보는 영상별 한 번만 저장한다.
앞뒤 문맥/본문이 같은 cue를 반복 참조하더라도 그 텍스트를 중복 저장하지
않으며, 공통 프롬프트 지침 역시 영상별 1회만 저장한다. 창별 cue 번호,
패킷 SHA-256, 세션·영상 ID, 경계 재검토 경고, 배치 순서는 남겨둔다.
`reconstruct_full_source_plan`은 각 창의 원문 패킷, 배치 및 전체 계획의
SHA-256을 원본과 완전히 일치하도록 복원하는 검증 함수다.

2026-11-02 실제 #1~#5 **미분석 338개 문맥**에 적용한 결과:
29개 원본 배치, 중복 제거 전 2,223,034바이트에서 후 1,168,684바이트로
**47.4% 축소**, 원본 cue·해시 손실 0건. 원본 전문이 포함된 파일은
소유자 전용 비공개 저장소에만 보관하며 GitHub에 포함하지 않는다.

**주의:** 압축이 ChatGPT의 분석 연산량을 47.4% 줄인다는 뜻은 아니다.
대화 모델은 필요한 각 자막 cue를 실제로 읽어 금융 의미를 해석해야 하며,
압축된 계획만으로 미해석 자료의 금융 사실이 자동 생성되지 않는다.
