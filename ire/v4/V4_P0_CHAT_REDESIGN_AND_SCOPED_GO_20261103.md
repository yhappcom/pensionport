## 결함 및 설계 결정
기존 P0는 사용자 요청 1회로 ChatGPT가 수행하는 유한 연구(U1)와 일반 Chat이 보장하지 않는 지속 호스트 작업/무인 재실행(U2)을 같은 필수 승인 게이트에 묶었다. 이 설계에서는 정상적인 Chat 연구와 결정적 체크포인트가 통과해도 P1 구현을 시작할 수 없는 거짓 병목이 발생한다.

**새 승인 경계**:
- **P0-C (필수)**: 일반 채팅에서 최초 사용자 요청 1회, 신규 V3 적응형 원본문맥 12개 분석, 모든 primary cue 상태 및 원문 인용, 불변 검증 영수증과 재실행 가능한 로컬 복구, 미확정·검증 한계 명시. 성공 시 `GO_BOUNDED_CHAT_TO_P1` (P1 개발 착수 허용), 사실·자문·장기 무인 처리 인증 아님.
- **P0-R (선택)**: 호스트가 별도 사용자 메시지 없이 대화 종료·충돌 후 자체 실행을 재시작하는 능력. 실제 지원 호스트/작업 ID/사고 로그에서만 `GO_HOST_AUTORESTART` 승인. 일반 채팅에서 `NOT_PROVEN`이어도 P1/P2/P3/P4의 **검증 가능한 분할 실행 개발**을 차단하지 않는다.
- 사용자는 채팅에 최초 지시 후 현재 응답 가능한 범위에서는 추가 `진행` 없이 지속 작업한다. 채팅 종료·실행 한계 초과 후 미래 턴에서 재개가 필요할 수 있음을 명시한다. 이 조건을 무조건적인 U2/U3/무인 완주라고 표현하지 않는다.
- 실전 금융 사실 승인/독립 골드/개인 자문 적합성은 P2–P4의 별도 게이트이며 P0-C GO로 승격 불가.

## P0-C 수락 기준
1. 실제 비공개 SRT 및 정확한 V3 적응형 분할과 원본 SHA 재현. 기존 구형 120문맥 P0 시험은 **폐기**하고 81문맥 V3 계획만 인정.
2. 사전 고정된 신규 12문맥에서 primary cue 100%를 LINKED / 구체적 NONCLAIM_CANDIDATE / UNRESOLVED로 각각 분류하고, 모든 주장에 실제 primary cue 정확 인용·유효 측정 단위를 부여. UNRESOLVED는 숨기지 않음.
3. 단일 사용자 요청 내 모델이 실제로 의미 초안을 작성했음을 기록. Python 검증기가 AI 분석을 했다고 주장 금지. 외부 모델 API 호출 0.
4. 별도 비공개 경로에 중복·변조 방지 불변 영수증 저장. 강제 프로세스 종료 뒤 추가 사용자 *창별* 입력 없이 원본 재확인·안전한 재실행 가능. Python 파일 복구는 호스트 자동 재개와 구분.
5. 위조 인용, 과거 문맥 혼동, cue 역참조 누락, 영수증 변조·중복 저장은 fail-closed.
6. 사용자 ZIP·개인 분석 원문·음성 전사문을 공용 GitHub에 공개하지 않음. 기존 V3 v003 및 main/연구 원장 불변.
7. 리포트에서 source-grounded provisional / independent fact / advisory eligible를 반드시 별개로 보고.
