## 매 PR의 Definition of Done

1. 변경 이유가 실제 원본 실패/사용자 목표에 연결돼 있다.
2. 최소 하나의 **실패 재현 테스트가 수정 전 실패·수정 후 통과**한다.
3. `python -m unittest discover -s ire/tests`에서 기존 V3 회귀시험 유지.
4. 원본/민감정보 공개 저장소 유입 0, 기존 `main`/V3 연구 파일 변경 0.
5. 완주 로그는 동일 run ID로 재현 가능하고 미해결·중단·확정·거절이 구분된다.
6. 실제 사람의 검토, 모델 해석, 공식자료 검증을 코드의 합성 테스트로 대신하지 않는다.
7. 요구 호스트가 실제 지원되지 않으면 코드 추가보다 우선 `NO_GO` 기록.
8. 승인받지 않은 본인 계좌 조작/투자 주문 기능 없음.

## 유의사항

- 기존 V3 코드 310개 시험은 새 V4가 독립 완주한다는 증거가 아니다.
- `V4` 시작 시 V3 특화 코드를 전부 다시 작성하지 않는다. 깨끗한 wrapper와 비공개 이벤트 원장부터 구현한다.
- P0에서 Work 실행이 확인되지 않으면 P1 이후 작업은 설계안일 뿐이며 기존 방법을 무인 완주라고 발표하지 않는다.

## 2026-11-03 P0-C 기반 새 실행 순서 (기존 의존 그래프보다 우선)
P0-C bounded Chat feasibility GO → P1 V3 정식 접수/안전 재개 → P2 #1 전수 → P3 #1~#5 통합 → P4 독립 평가. 지속 호스트 자동 재시작은 별도 P0-R 선택 연구다.

P0-C 실원본 12문맥/182 primary cues/44 잠정 주장/179 직접 인용 검증, 로컬 7개 공격·재개 테스트 통과로 **P1 착수 가능**. P1 첫 번째 테스트는 ConversationResearchSession의 실제 V3 adaptive packet 구조·halo·cue 상태를 사용해 현재 독립 실험용 초안 12개를 정식 V3 accept/gate에 집어넣되, 기존 v003·main·원본은 읽기 전용으로 보호한다. 유효하지 않은 창은 BLOCKED_SEMANTIC과 이유 기록 후 수정한다. 실제 사용자 추가 메시지/도구 한도에 대한 영속성을 보장하지 않는다. 전체 결정 기록은 [P0 개정안](V4_P0_CHAT_REDESIGN_AND_SCOPED_GO_20261103.md).


## 2026-11-03 후속 최종 결정 — P0-R 필수 관문 복원
사용자가 원래 정의한 무인 연구 완주의 필수 조건을 재확인했다. P0-C GO는 유한 Chat 소프트웨어 시험의 성공만 의미하며 **P0 전체 GO 또는 P1 개발 승인으로 사용 금지**. P0-R의 실제 호스트 자체 자동 재개 실증 및 신규 12문맥 완료가 통과하기 전 **P1~P4 본격 실행·운영 개발 승인 보류**. 이전 P0-R 선택/비차단 문구와 충돌하는 부분은 [최신 P0 필수 관문 결정](V4_P0_MANDATORY_HOST_RECOVERY_GATE_20261103.md)이 우선한다. 이 내용은 이전 실험 성적을 취소하거나 실제 호스트 시험을 수행했다고 주장하지 않는다.
