# IRE V4 P0 요구사항 최종 정정: 단일 명령 통합 연구 완결성
2026-11-03 · 사용자 요구 직접 확인에 따른 우선 결정

## 사용자 의도
채팅의 연구 명령 **1회**가 입력되면, 해당 요청을 수행하는 오케스트레이터가 원본 수집/무결성, 전체 금융 의미 분석, 공식자료 독립 검색, 수치·범위·시점 검증, 반증·정정·누락 검수, 기존 영상·지식 원장 대조, 근거별 누적 결과, 자문 적합성 분리 및 최종 보고까지 통제해야 한다. 사용자는 창마다 다시 '진행'을 요청하지 않는다.

사용자가 요구한 것은 채팅 종료·서버 종료 이후 **자동으로 새 채팅을 열고 무인 재시작하는 기능이 아니다.** 기존 P0-R 호스트 자동 재시작 요구를 필수 관문으로 지정한 설계는 요구 오독이며 철회한다.

## 수정 P0: ONE_COMMAND_CLOSED_RESEARCH
실제 모델 의미 판단 주체는 현재 ChatGPT 대화/지원 모델 호스트. Python은 유한하고 결정적인 원본 검증, 패킷 준비, 영수증 저장, 검증 게이트를 수행. 별도 모델 API나 비공식 Chat API 흉내는 금지.

P0-1: 원본 SRT ID/SHA/cue/적응형 문맥 및 기존 승인 데이터 대조
P0-2: 사용자 요청 한 번 아래 실행 계획·미처리 큐 생성
P0-3: 각 창에 대해 실제 모델 원자 주장/비주장/미해결 판단
P0-4: 원문 SHA/직접 인용/조건/인과/숫자·단위 감사 실패 시 동일 실행에서 재판정
P0-5: 공식 근거 검색·원문 효력일·범위/예외 대조, 근거 없으면 OPEN과 격리 사유
P0-6: 이전 결과와 SAME/EXTENDS/CONFLICT/TIME/DIFFERENT_SCOPE 관계 판정 및 불변 누적 diff
P0-7: 전수 cue census, 독립 재현 가능 영수증, OPEN/verified/fact/advisory 상태 분리 후 최종 완결 보고
P0-8: 사용자에게 '진행' 재요청 0회. 실증 실행이 도구/모델 호출 한도에 걸리면 STOPPED_LIMIT와 미처리 수량을 **정직하게** 보고한다. '완료'라고 거짓 표시하거나 무제한 단일 응답을 보장하지 않는다.

## GO 게이트 (아직 미실증)
최소 #1 전체 81 V3 적응형 문맥의 **실제 한 번의 사용자 요청으로** 전수 의미 분석·근거별 검수·기존 지식 대조·최종 보고를 완주하는 실증을 P0 GO 선결 조건으로 삼는다. 한 번의 명령에 대한 연속 모델 판단이 실제 도구 로그/원문 인용/비공개 영수증과 함께 검증되어야 한다. 12창의 단편 분석/로컬 Python 복구/합성 CI는 이 GO를 대체할 수 없다.

추가 #1~#5 346문맥 통합 실증은 후속 P2–P3에서 확대하고, P4는 신규 독립 인간 블라인드 정답 및 자문 안전을 승인한다. 법령 확인 불가 항목은 OPEN으로 남긴 **연구 보고 완결**은 허용하지만 인증된 사실·개인 자문으로 자동 승격하지 않는다.

## 구정책 관계
이 문서는 기존 'P0-R 자동 재시작 필수' 결정과 'P0-C 12문맥 실증을 P1 GO로 간주'하는 결정을 **모두 대체**한다. 기존 로컬 복구/검증기와 자율 호스트 탐색은 부가기술로 보존하지만 사용자 요구의 P0 승인 기준은 아니다. P0 현재 상태: DESIGN_CORRECTED; ONE_COMMAND_END_TO_END_NOT_YET_PROVEN; P1~P4 본격 릴리스 미승인.
