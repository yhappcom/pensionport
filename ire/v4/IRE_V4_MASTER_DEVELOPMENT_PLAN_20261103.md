# IRE V4 — 독립 실행형 투자 연구 엔진 재설계 및 개발 기준서

> **문서 상태:** 설계 RFC · 개발 착수 기준안 · 기능 구현/실전 완주 승인 아님  
> **판본:** 1.0-draft · **작성일:** 2026-11-03  
> **대상 저장소:** `yhappcom/pensionport` · **보호 범위:** `main`, V1–V3 연구·원본·불변 정정·개인 자료  
> **핵심 제약:** 별도의 모델 API를 사용하지 않고 현재 ChatGPT 제품 및 허용된 연결 도구를 활용한다. 

## 0. 결정 요약

**개발은 권고하되 P0 실행 호스트 실증을 통과하기 전 V4 전면 구현을 승인하지 않는다.** 기존 V3의 출처 인증·증거 원장·금융 의미 감사·관계 평가·누적 원장·자문 차단 코드는 재사용한다. V4의 신규 가치는 *단일 사용자 요청을 지속적인 연구 실행으로 전환하는 호스트 실행 계층*, *작업 상태/복구*, *완료와 미확정의 범위 구분*이다.

- 목표 A — **단일 사용자 요청**: #1~#5 분석을 한 번 지시하면 추가적인 '진행' 메시지 없이 가능한 범위의 연구를 이어간다.
- 목표 B — **연구의 닫힌 결과**: 원문 전수 처리, 원자 주장, 근거별 검증/보류, 이전 연구와 관계 대조, 변경 이력, 최종 리포트까지 한 연구 실행으로 묶는다. 보류는 숨기지 않고 `OPEN`으로 기록한다.
- 목표 C — **누적 자문 활용**: 검증 범위가 명시된 주장만 검색하고 현재 법령·적합성·상충 위험을 별도로 평가한다. 미승인 사실로 개인 거래를 권고하지 않는다.
- **보장할 수 없는 주장**: 일반 Chat에서 모델 재호출 API 없이 Python이 ChatGPT를 무제한 반복 실행하거나, 임의 길이의 영상 연구가 무조건 단일 응답에서 완결된다는 주장.

### 1.2 현재 이용 가능한 실행 환경에 대한 외부 조사

1. **일반 Chat + 로컬 Python:** 원본·체크포인트 검사와 답변 접수는 가능. 단 Python이 같은 ChatGPT 모델을 다시 실행하는 공식 사용자 인터페이스가 없으므로 완주 제어주체로 **부적합**.
2. **ChatGPT Work (우선 실험 후보):** 공식 도움말에서 장시간 다단계 연구, 파일/앱 연계, 작업 지속, 클라우드 작업을 설명한다. 그러나 계정 권한, 작업 한도, 일시 중단, 연결된 비공개 파일 접근, 도구 반복 실행은 **프로젝트 환경에서 미실증**. Python이 Work를 프로그래밍 방식으로 마음대로 호출할 수 있다는 근거도 없다.
3. **Work + 연결 도구/클라우드 컴퓨터:** 사용자가 Work 작업을 한 번 시작하고 호스트가 허용된 파일·도구를 이어 쓰는 구조가 현실적인 가설. CLI는 **Work가 호출 가능한 범위에서만** 사용한다. 웹 브라우저를 통한 계정 인증·파일 다운로드·파이썬 실행 가능성은 별도 P0 확인 대상.
4. **Scheduled Tasks / 이벤트 실행:** 주기/트리거에 의존하며 프로젝트 내 업로드 파일 접근 제약이 공식 안내에 존재한다. 영상 5편 전체를 무인 처리하는 실행 엔진으로 **선정하지 않는다**. 필요하면 완료 보고·재점검 알림의 보조 수단만 사용한다.
5. **GitHub Actions:** 정해진 코드·합성 회귀검사·공개 비식별 보고에 적합. 모델 추론의 주체가 아니며 비공개 SRT·개인 자료를 공개 저장소로 전송하는 우회로로 사용할 수 없다.
6. **별도 모델 API 런타임:** 통제력 높은 대안이나 사용자 제약상 **현재 범위 제외**. 제약이 변경되기 전 설계·코드에 의존성 주입 금지.

**공식 참고 (2026-11-03 접근):** [ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex), [Using cloud browser](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt), [Scheduled tasks](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt), [GitHub Actions workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax). 제품 가용성은 계정과 릴리스 상태에 따라 다르므로 실제 접근 권한을 추정하지 않는다.

### 1.3 실패 근본 원인

- 모델 추론을 수행하는 호스트와 Python 검증기가 분리되어 있고, Python이 모델 실행을 재호출하는 계약이 없다.
- 소프트웨어 테스트와 금융 의미 재현율을 한 개의 '엔진 완성' 지표로 혼동했다.
- 검증 완료 전까지 전체 지식 통합을 막는 설계는 안전하지만, 보류 주장이 다른 독립 주장까지 무조건 정체시키는 병목이 있다.
- JSON 크기·반복 cue를 줄여도 **실제 의미 추론량과 독립 검증 수**는 줄지 않는다.
- 중단 복구는 저장 관점에서만 성립했고, 호스트가 재개 작업을 실제로 다시 수행하는 능력은 검증되지 않았다.

## 2. 성공 기준: 한 턴과 완료를 세 수준으로 구분

| 수준 | 명칭 | 판정 방식 | V4 약속 |
|---|---|---|---|
| U1 | `ONE_USER_REQUEST` | 사용자의 최초 연구 요청 1회; 추가 `진행` 명령 0회 | **최우선 필수 요구** |
| U2 | `ONE_HOST_TASK` | 하나의 Work/지원 호스트 작업 안에서 반복 실행, 체크포인트, 최종 보고 | **P0에서 실증 후 목표 채택** |
| U3 | `ONE_CHAT_RESPONSE` | 현재 Chat의 단일 응답 실행 제한 안에 임의 규모 전수 완료 | **보장 금지** |

다음 *서로 다른 완료 상태*를 혼동하지 않는다.

- `SOURCE_COVERAGE_COMPLETE`: 요청된 원본 파일의 대상 cue 전수 배정/검토 완료. 원자 주장·비주장·미해결 사유 모두 원문에 연결됨.
- `RESEARCH_REPORT_COMPLETE_WITH_OPEN_ITEMS`: 검토한 금융 발언·근거·반론·관련 기존 지식·미해결 항목이 빠짐없이 보고되고 재실행 가능한 연구 기록으로 봉인됨. 미확정 항목 존재 가능.
- `FACT_VERIFIED_IN_SCOPE`: 개별 원자 주장의 기준일·관할·상품·조건에 대해 해당 공식 원문과 심사 증빙이 충분함. **주장 단위 승인**.
- `ADVISORY_ELIGIBLE`: 질문·이용자 맥락의 범위/시점/위험·적합성 검증까지 통과. 연구 완료만으로 자동 도달 불가.

`BLOCKED_HOST`, `BLOCKED_SOURCE`, `BLOCKED_EVIDENCE`, `BLOCKED_INDEPENDENCE` 등은 완료가 아니라 명시적 중단 사유다. 외부 승인·로그인을 기다리는 상태도 성공이 아니다.

## 3. 최종 시스템 아키텍처

```
사용자 요청 1회
    │  └── Host Capability Probe: Work/Chat 접근권한·도구·지속·재개
    ▼
V4 Host Task Supervisor [호스트 안에서 작동하는 연구 지시 및 도구 루프]
    │  Planner / Budgeter / Source Fetch / Model Meaning Step / Reviewer
    │  실행한도·연속 처리·상태전이 / 오류 코드 / 허가 요청
    ▼
Durable Run Ledger & Event Store (비공개, 원본 SHA/리비전 CAS)
    │
    ├── SourceRegistry ─── 원본 SRT, cue ID, 창·인용
    ├── MeaningQueue ───── 단위 주장, 조건·예외, 의견/가정 구분
    ├── GroundingGate ──── 기존 V3 검증기/인과·수치·원본/인용
    ├── EvidenceService ─ 공식 근거 검색·원본 저장·효력일/범위
    ├── RelationEngine ─── 중복/보완/충돌/시점 변화/조건 차이
    ├── KnowledgeStore ─── 주장별 검증 층위·불변 통합 버전
    └── AdvisoryGate ───── 자문 질문별 근거·적합성·상충·검증 한도
    ▼
Final Run Report + Scope-Limited Knowledge Release + OPEN Queue
```

### 3.1 호스트와 엔진의 엄격한 책임 경계

- **호스트(ChatGPT Work 후보)**: 원문 읽기, 의미 판단, 필요한 공식 검색·해석, 검토 의사결정, 도구 호출, 미완료 루프 반복, 최종 서술.
- **Python V4 코어**: 작업 계획·진행률·SHA·정규화·스키마·계산·원본 대조·근거 문서 저장·불변 이벤트·가드·지식 통합의 *결정적 기능*. 모델이 내놓지 않은 의미 주장을 생성하지 않음.
- **독립 인간 평가자**: 블라인드 금융 주장 골드·상충 조정·전문 판단, 별도 신원·독립성 확인. 모델 자기평가는 독립 평가가 아님.
- **공식 발행 기관**: 법령/금융상품 현행 원문. URL이 공식 도메인이라는 이유만으로 모든 날짜·조항 적용이 승인되지는 않음.

**금지 설계**: 브라우저를 기계적으로 조작해 숨겨진 비공식 Chat API를 흉내 내는 방식, 사용자의 승인 없이 본인 계좌를 읽거나 주문하는 방식, 원본 자막을 공용 GitHub에 복제하는 방식.

### 3.2 작업 단위와 순서

`ResearchRequest → Run → Video → Window → AtomicClaim → ClaimEvidence → ClaimRelation → KnowledgeRevision → AdvisoryView`.

각 원자 주장은 `video_id`, `original_sha256`, `cue_ids`, `exact_quote`, `window_id`, `answer_sha256`, `claim_id`, `time_scope`, `jurisdiction`, `product`, `actor`, `action`, `condition`, `unit`, `negation`, `exception`, `speech_type`, `status`를 가지며 모델 추론/공식자료의 별도 출처를 구분한다. **기존 저장된 주장 번호는 변경하지 않으며**, V4 고유 키는 `source_sha256 + window + claim ordinal + revision`의 안정적 지문에 기초한다.

발언이 겹치는 자막에서는 시간 중첩만으로 주장 중복이라 단정하지 않는다. 모든 *primary cue*의 커버리지를 보장하고 *halo cue*는 근거 인용용 문맥으로만 사용한다.

### 3.3 실행 상태 기계

```text
CREATED -> CAPABILITY_CHECK -> SOURCE_LOCKED -> PLANNED -> RUNNING
RUNNING -> CHECKPOINTED -> RUNNING           (자동 재개)
RUNNING -> SOURCE_REVIEW -> EVIDENCE_REVIEW -> RELATION_REVIEW -> REPORT_SEALED
RUNNING -> PAUSED_HOST|PAUSED_APPROVAL|BLOCKED_INPUT|BLOCKED_SEMANTIC
REPORT_SEALED -> KNOWLEDGE_PROVISIONAL -> REVIEW_RELEASED (범위제한)
REVIEW_RELEASED -> ADVISORY_ELIGIBLE          (별도 질문/적합성 확인)
```

- 전이마다 `run_id, attempt, event_sequence, state_before/after, source_digest, code_commit, actor_type, input_sha, output_sha, error_code, created_at`을 append-only 저장한다.
- `idempotency_key=(run_id, video_id, window_id, effective_revision, action)`; 동일 요청 재전송은 동등한 응답만 허용한다.
- 상태 갱신은 compare-and-swap(기존 버전 일치할 때만 쓰기), durable fsync/SQLite WAL/원자 rename, 전원·프로세스 재시작 시 재생(replay)을 설계 요구로 삼는다.
- 원장 commit은 **원본 연결 주장**과 **해당 근거의 층위**를 함께 기록한다. 중요한 미확정 주장 하나가 무관한 전체 영상의 연구 보고 생성까지 영구 차단하지 않되, 검증되지 않은 주장을 VERIFIED 테이블로 승격할 수 없다.

## 4. 신규 엔진의 구성 요소 및 재사용 범위

| V4 모듈 (제안) | 재사용할 V3 | 새로 구현할 부분 |
|---|---|---|
| `host_probe` | 없음 | Work/Chat 실제 실행·도구·재개·파일 접근 능력 시험 |
| `run_supervisor` | `v3_one_turn`, `v3_orchestrator` | 호스트가 실행할 FSM, 자동 루프, 중단 시 복구 영수증 |
| `semantic_runner` | `chat_bridge`, `v3_semantic_audit` | 명제별 작업 분할, context budget, 의미 재검토 업무화 |
| `provenance_gate` | `source`, `v3_claim_quality`, `v3_numeric` | 원문 전체 의미/관계 귀속의 변경 전후 체크 |
| `evidence_coordinator` | `v3_evidence`, `v3_evidence_txn` | 기관·기준일별 검색 큐, 변경/폐지 증거 재검증 |
| `relation_integrator` | `knowledge`, `v3_relation_review` | 주장별 중복/보완/상충/유효기간, 승인 단위 병합 |
| `research_reporter` | `v3_release`, `v3_advisory` | OPEN 사항 포함 최종 문서·누적 변경 보고 |
| `eval_harness` | `v3_blind_protocol`, `v3_relation_eval` | 새로운 숨김 골드·정밀도/재현율·실제 완주 재현 실험 |

기존 V3 모듈은 얇은 adapter를 통해 **읽기 전용**으로 호출한 뒤 V4 독립 저장소 구조를 확립한다. 바꾸어야 한다면 해당 기존 테스트 310건의 결과를 그대로 비교하고 명시적으로 마이그레이션한다. 새 설계 문서만 작성하는 단계에서 코드 동작을 바꾸지 않는다.

## 5. 실패 정책과 결과 신뢰도

| 사건 | 상태 | 처리 | 사용자 보고 |
|---|---|---|---|
| Chat/Work 호스트 실행 또는 재개 불가 | `BLOCKED_HOST` | 전 단계 미승격, 호스트 선택 재검토 | 자동 완주 불가능하다는 사실 명시 |
| 개인 비공개 원본 접근 실패 | `BLOCKED_SOURCE` | 해당 영상을 멈추고 소스 요청 | 누락 영상·파일만 보고, 타 영상 진행은 정책에 따름 |
| cue 인용 누락/금융 비주장 오판 | `BLOCKED_SEMANTIC` | 해당 창만 재분석; 원본 수정 금지 | 누락 cue·분석률 별도 표시 |
| 인과·단위·규정 시간차 | `OPEN_SEMANTIC`/`OPEN_EVIDENCE` | 해당 주장 격리, 관련 독립 주장 연구는 진행 | OPEN 이력·영향 범위 공개 |
| 원문·답변의 SHA 변조 | `REJECTED_TAMPER` | 원본 잠금, 쓰기 금지, 보안 이벤트 | 원문은 노출하지 않고 오류 보고 |
| 모델/도구 실행량 초과 | `PAUSED_HOST` | 안전한 체크포인트+자동 재개 조건 기록 | 이를 완주로 표기하지 않음 |
| 공식 근거 못 찾음 | `OPEN_EVIDENCE` | 검색 범위 기록·재검색 조건 부여 | 검증된 사실로 승격 금지 |
| 독립 평가자 기록 없음 | `BLOCKED_INDEPENDENCE` | 연구 보고는 가능, 정확도 인증 불가 | 독립 정확도 미측정 명시 |

## 6. 개발 단계 및 Go/No-Go 관문

### P0 — 실행 호스트 실증 (가장 먼저)

**핵심 질문:** 별도 모델 API 없이 사용자가 *한 번* 시작한 지원되는 Work 작업이 실제 비공개 SRT를 읽고, 모델 의미 판단 → 검증 CLI/연결 도구 → 다음 창 → 최종 보고까지 **추가 사용자 메시지 없이 반복하는가?**

- Work 사용 권한/클라우드·로컬 파일 접근/코드·GitHub/Google Drive 사용 가능성/작업 지속·승인 프롬프트를 실제 계정에서 기록한다.
- #1 원본에서 **서로 다른 12개 미분석 연속 문맥**을 요청 한 번으로 처리한다(원본 실제 SHA·금융 주장·비주장·미확정 전수 기록).
- 동일 P0를 고의 중단 후 재개·권한 거부·누락 근거·중복 재접수 시나리오로 반복한다.
- **GO**: 같은 작업 실행에서 12/12 누락 없이 처리, 추가 '진행' 메시지 0회, 원문 SHA·완전한 체크포인트, 종료/재개 증거 확보, 모델 추론이 실제 수행됐음을 로그/산출물로 확인.
- **NO-GO**: 모델 실행 연결 없이 Python 접수만 됨; 호스트 스스로 다음 창으로 진행 못 함; 사용자에게 매 창마다 새 메시지를 요구; 원본 접근 불가; 재개 불능.
- `NO-GO`이면 대량 구현을 중단한다. Work로 가능하지 않은 일을 스크립트로 가능하다고 포장하지 않는다. 사용자 제약을 바꾸거나 `실행 중 사람 개입`을 인정한 별도 목표로 RFC를 수정한다.

### P1 — Supervisor 최소 동작 제품

P0 GO 후 상태기계, 이벤트 원장, host-action protocol, 12문맥 연속 실행, 안전 재시도, 문맥 단위 거절·재처리, 결과 보고를 구현한다. **통과:** 의도적인 3가지 장애(프로세스 종료/네트워크 오류/중복 제출)에서 의미·원본·승인 상태 동일하게 회복.

### P2 — 실제 한 편 전수 연구

#1 영상 모든 문맥을 단일 요청으로 분석(기존 8개와 새 분석 구분), 발언의 조건/인과/수치/관할·기준일 대조, 공식 검증 후보 큐를 완성하고 잠정 연구 보고서를 봉인한다. **통과:** cue 전수 커버리지 100%, 보고서·미해결 원장·근거 범위와 다음 검증 계획이 일치, 사용자 `진행` 요청 0회, 복원 재현.

### P3 — #1~#5 누적 연구 실증

346개 전체 문맥의 원본문맥 추출, 5편 교차 관계 분석, 기존 지식 대비 `SAME/EXTENDS/CONFLICTS/TIME_SUPERSEDED/DIFFERENT_SCOPE/UNRELATED/PENDING` 판정, 분기·조건·시점별 병합. **통과:** 5편 소스 커버리지 100%, 내용 없는 `완료` 없음, 누적 원장 CAS/재시도 통과, 비공개 원본 미유출. 외부 검증 불가 항목은 OPEN으로 남겨 연구 보고만 닫는다.

### P4 — 신규 독립 블라인드 성능·자문 검증

두 독립 검토자와 제3 조정자가 과거 ChatGPT 답변/현재 채팅에 노출되지 않은 신규 홀드아웃을 평가한다. Precision/Recall/F1, 금융상품·수치·조건·부정·예외별 누락, 관계 Recall@K, 자문 보류·안전성 측정. **통과:** 미리 승인한 표본수·하한·실수 위험 기준 충족. 미충족이면 제품/자문 승인 차단.

### P5 — 운영·추가 791편 확장

1~30편 단위의 재개 가능한 작업 세그먼트, 신규 영상의 이전 승인 근거 재검토, 통합 리포트·변경 이력·검색 노출 수준 확인. **통과:** 지정 반복 배치에서 호스트 완주 재현, 비용·도구 한도·평균처리량 측정, 장애 시 조용한 누락 0건.

## 8. 개발·보호 원칙

1. **별도 브랜치:** V4 설계와 신규 코드는 기존 V3 feature 기준 별도 `feat/ire-v4-*` 브랜치. `main` 수정 금지, 기존 PR 수정·병합 금지.
2. **원본·민감 자료:** 원본 SRT, 원자 주장 전문, 투자자 정보, 비공개 영수증은 개인 비공개 저장소에만. 공용 GitHub는 코드·계약·합성 테스트·비식별 수치만.
3. **쓰기 권한 최소화:** 프로젝트/연구 원장, 계좌·주문 시스템을 분리. 주문·송금·매매 기능은 V4 범위 밖.
4. **공식 문서 품질:** 날짜, 개정/폐지, 기관 도메인, 원문 바이트 지문, 예외 조건, 관할, 동일 명제의 충돌 기록 보존.
5. **승인 구분:** `RESEARCH_DONE`과 `VERIFIED_FACT`·`ADVICE_OK`는 서로 다른 독립 게이트. 합성 CI 100%만으로 승인 금지.
6. **기존 V3 보존:** 310 테스트를 baseline으로 무변경 통과. V4 신규 테스트/실원본 재생산 시험 추가. V3 실행기를 덮어쓰지 않음.
7. **작업 제한:** 비용·토큰·시간·도구 호출·원본 외부 전송을 예산으로 추적. 초과 시 조용히 생략하지 않고 상태 보존 및 STOP/RESUME.
