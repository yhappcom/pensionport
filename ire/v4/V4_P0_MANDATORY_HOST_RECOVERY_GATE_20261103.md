# IRE V4 P0 필수 관문 재확정 — 2026-11-03

## 사용자 요구/결정
단일 사용자 요청으로 연구가 중단 없이 계속 수행되고, 실행 중단 뒤에도 필요한 경우 **호스트 스스로 다음 작업을 수행하는 능력**은 투자 연구 엔진의 핵심 기능이다. 따라서 P0-C의 유한한 12문맥 시험을 P0 전체 GO로 선언해서는 안 된다. **P0-R은 다시 필수 게이트로 지정**한다. P0-R이 실제 호스트 시험에서 통과하기 전에는 P1–P4의 본격 실행·운영 개발 승인을 내리지 않는다.

## 현 상태
- P0-C: Chat 내 유한 신규 12문맥, 182 primary cues, 44 잠정 원자 주장, 179 직접 인용 및 7 로컬 복구/적대적 시험의 **범위 제한 시험 통과**. 데이터 및 의미 정확도 인증은 아님.
- P0-R: 실제 호스트 작업 ID, 호스트 모델 반복 실행, 호스트 스스로 재시작/재개/남은 작업 완료에 대한 관찰 기록 없음 → **BLOCKED_UNPROVEN**.
- P0 전체: **BLOCKED**, GO 아님.
- P1–P4: 본격 실행·운영 개발 승인 보류. 기존 V3 코드와 문서 보존.
- 2026-11-03 작성된 P0-C 단독 GO 허용 문서는 유한 채팅 시험의 기록으로 보존하지만, 전체 P0/P1 승인 정책은 이 결정이 우선한다.

## 지원 실행 호스트 실증 요구
1. 사용자 원 요청 한 번으로 호스트 작업을 개시하고 안정적 task/run ID 수집.
2. 비공개 실제 SRT #1 원본의 신규 V3 adaptive 문맥 12개를 모델이 **실제로 각 차례 신규 의미 판단**. 기존 초안 복제나 Python의 단순 수신은 불가.
3. 최초 4문맥 후 **호스트 실행 자체**를 중단시키고, 사용자 추가 '진행' 메시지 없이 지원되는 방식으로 다시 실행되도록 관찰. 체크포인트 4개 유지/중복 0.
4. 남은 8개 문맥에 대해 모델 판단, 정식 원문 인용/재검증, 12/12 원본 cue census, 최종 서명된/해시된 보고서 생성.
5. 권한 만료, 잘못된 패킷, 중복 제출, 네트워크 오류 각각에서 실패 격리 및 안전한 복구. 외부 모델 API 0, 비공개 SRT 공개 전송 0.
6. 같은 실험의 로그·도구 호출 흔적·결과 파일을 검토 가능하게 제공해야 GO. 호스트 접근권한이 없거나 지원되지 않는다면 **실패 이유와 실제 지원되는 대체 실행 주체**를 명확히 밝혀야 하고 '곧 자동화될 것'이라고 발표할 수 없다.

## 플랫폼별 역할 구분
- 일반 Chat: 유한 모델 의미 판단·파일/도구 호출 가능. 호스트 자체가 세션 종료 뒤 무인 재시작한다는 기능은 이 프로젝트에서 미입증.
- Python/CLI/GitHub Actions: 체크포인트와 결정적 검증/CI 가능. 독립적으로 ChatGPT 채팅 모델을 재호출할 API가 없으므로 P0-R 대체 불가.
- Automations/Scheduled Tasks: 별도 스케줄로 새 작업을 시작하는 기능으로, 원 실행 task ID와 모델 작업 상태·비공개 파일·호스트 복구를 자동 보증하지 않는다. 유저가 승인한 예약 일정 없이 재개 기능의 우회 증명으로 생성하지 않는다.
- ChatGPT Work 및 기타 지원되는 지속 실행 호스트: 실제 권한·파일 접근·모델 반복·재개를 확인해야 후보로 채택 가능. **검증 전에는 GO 아님**.

## 해결책의 의사결정
(A) 공식적으로 지원되는 지속 실행 호스트가 P0-R 조건을 충족하면 동일한 원본/체크포인트/수락 검증기로 P0 GO. (B) 사용자가 현재 일반 Chat만 허용하는 경우, 기술적으로 입증 가능한 기능은 '다음 사용자 실행에서 정확한 체크포인트 재개'까지다. 이것은 P0-R 및 원래의 완전 무인 완주를 만족하지 않으므로 GO 금지. (C) 외부 모델 API 사용은 현재 사용자 제약으로 제외.

**다음 선행 실증:** 지원 호스트의 실제 task ID·중단·자율 재개 로그 확보. 이 결과가 없는 한 다른 계획 변경·CI 성공을 P0-R 실증으로 대체하지 않는다.
