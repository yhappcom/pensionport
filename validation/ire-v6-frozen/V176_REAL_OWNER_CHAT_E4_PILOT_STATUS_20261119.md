## 실제 수행

동일한 원본 자막 바이트(SHA-256 `638fefee007aa9122e68717b922194410ebbd7913a619bb9354f09af14468a0d`) 1,481개를 **V176 엔진이 원본부터 읽고** 13개 기술 구간으로 인덱싱하였다. V175 이전 원자 판단·승인 원장은 불러오지 않았다.

V176 엔진이 순서대로 자막 1~8, 9~16, 17~24, 25~32를 현재 채팅에 요청하고, 현재 대화에서 ChatGPT가 실제로 자막·주변 문맥을 검토해 원문 SHA·화자 불확실성·발화 행위·보류 사유를 포함해 반환했다. 엔진은 4개 배치에 대해 요청 SHA와 SQLite 이전 헤드를 확인해 4개 원본 분류 이벤트를 저장하고 정확한 다음 자막(33번)으로 이동했다. 같은 응답을 재전송하면 멱등 처리된다.

실제 원자 1건은 30~32번 자막에 걸친 도서 저자 서지 발언이다. 엔진이 서지 근거 검색 작업을 발행하자 ChatGPT가 원서 발행사 Wiley와 한국어판 책 서지를 실제 검색·비교했다. 해당 응답은 `PUBLISHER_ATTRIBUTION_ONLY` **잠정 서지자료**이며 실제 출판사 원문 바이트의 E4 HTTPS 인증은 이 세션에서 하지 않았다. 투자 사실의 신뢰성/금융 규칙의 적용성은 이 서지 근거로 승인하지 않는다.

엔진은 `compile_native_v6_stage()`에서 **동결 `ire.v6.atomic_exchange.audit_host_atomic_exchange`** 함수를 실행해 모든 1,481개 자막의 현재 상태를 검사했다. 미분류 1,449건과 의미 보류 7건은 `UNRESOLVED`로 보존한다. V123이나 E4를 자동 PASS로 바꾸는 함수는 호출하지 않는다.

## 엔진 구조 변경

- `v176_chat_engine_loop.py`: 원본 SHA가 고정된 엔진 소유 작업 대기열, 실제 채팅 요청 생성, 원본 인용·주장·숫자 검증, 원자적 SQLite 커밋, SHA 이벤트 사슬, 재개·멱등·충돌 차단.
- 열린 문맥은 `RESOLVE_CONTEXT_CUES`로 확대 전후 문맥을 재요청한다. 최초 판단을 삭제하지 않고 재검토 이벤트로 보존한다. 여전히 OPEN이면 E4 HOLD로 종료한다.
- 근거가 필요한 실제 원자는 `SEARCH_ORIGINAL_PRIMARY_EVIDENCE`로 검색 과제를 발행한다. 확인된 웹 링크와 서지정보는 미검증 후보로만 보관한다. V166 동결 E4의 공식 원전 바이트 재검증을 대체하지 않는다.
- `run_host_cycle(chat_callback)`: **현재 채팅 호스트**가 실제 모델의 응답 콜백을 제공한 경우 단일 요청으로 여러 건의 원본 검토를 순회하는 제어 함수. ChatGPT를 Python이 자체 호출하거나 과거 판단 파일을 자동 생성하지 않는다.
- `v176_chat_engine_cli.py`: `next` → ChatGPT 실제 답변 → `commit` → `next`를 현재 채팅의 도구 호출로 연결한다. 종료/중단하면 비공개 원장의 정확한 위치에서 재개한다.
- **동결 원본 V123/E4 관문 및 E5 기능은 수정하지 않았다.** E4 검증 전에는 지식 발행이 발생하지 않는다.
