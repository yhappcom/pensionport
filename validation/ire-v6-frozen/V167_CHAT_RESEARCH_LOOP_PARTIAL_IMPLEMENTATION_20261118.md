# V167 — ChatGPT in-chat 연구 루프 연결 (E4 부분 개선)

**기준:** V166 PR #54의 HEAD `4398e171daece83cce12565d78f31eee5a56d603`, 별도 검증 브랜치. 기존 V123/V126/V128 및 보호 `main`은 수정하지 않는다.

## 확인된 근본 원인

- V166 E3는 이미 작성된 `CHATGPT_IN_CHAT` 검토 기록의 무결성을 확인하여 전달하며 ChatGPT를 호출하지 않는다.
- V166 E4 전체 영상 검사는 13개 구간과 293개 원자의 OPEN 수를 진단하지만, 새로운 의미 판정을 작성하거나 V123 검토 기록을 수정하지 않는다.
- 따라서 파일 재업로드나 OPEN 목록의 반복 수작업은 자동 연구 실행을 대신하지 못한다. E1–E3 구조 PASS와 실제 1편 의미 판정 종단 완료는 별개다.

## 이번 수정 범위

`v167_chat_research_loop.py`는 실제 원본 SRT·cue·13개 범위의 기존 V123 검토를 `v166_e4_full_video_readiness.audit_video_readiness`로 먼저 읽기 전용 검문하고, 모든 OPEN 원자를 누락 없이 작업표로 만든다. 고위험을 먼저 정렬하고 원문 발화·맥락·조건·예외·수치, 기존 원자/검토 해시를 작업에 유지한다.

`execute_chat_review_round`는 **호스트가 제공하는** 두 실제 콜백(근거 검색과 현재 채팅의 ChatGPT 검토)을 동일 작업 내 순서대로 호출하며, 근거 바이트·인용 및 결정 해시를 원자별로 재대조한다. 검색된 임의 자료를 공식 원전으로 자동 인증하지 않으며, 근거 없는 승인 후보, 누락된 문맥 검문, 위조된 claim ID·요청 해시를 차단한다.

결과는 **비공개 연구 제안서**로만 반환한다. 기존 V123 review의 결정을 직접 덮어쓰지 않고, E4 원문 발행자 재인증 및 유효일·범위 확인, native V123 재실행, 13/13 PASS, 부모 지식 원자적 저장의 모든 선행 조건을 그대로 유지한다.

## 한계 및 후속 종단 연결 조건

1. **모델 호출은 미구현:** 모델 API를 사용하지 않는 Python 코드가 현재 채팅의 ChatGPT를 마음대로 호출하는 기능은 없다. `chat_reviewer`는 현재 대화 오케스트레이터가 직접 제공해야 하며, 테스트 double은 실제 AI 추론 증거가 아니다.
2. **공식 근거 재검증은 기존 E4:** Callback이 준 URL·본문은 원본에서 실제 인용 문자열만 검사한다. 권한 있는 발행인의 TLS 원본·시점 및 실질적 함의는 `assess_e4_primary_authority_gate`의 검문 전에는 승인 불가다.
3. **최신 실물 재실행 미실시:** 2026-11-18 V166 최신 개정 193 OPEN 원장 ZIP은 이번 연결 검증 입력으로 확보하지 못했다. 기존 245 OPEN 구판을 최신 193 OPEN으로 오인하거나 검토 수를 부풀리지 않는다.
4. **실제 운영 연속 실행 미입증:** ChatGPT 콜백→정식 원자 수정 검문→V123 재실행→E4 PASS→V128 원자적 발행의 end-to-end 실원본 증거가 아직 없다. 운영 런타임에서 콜백이 공급되지 않는 경우 실패 폐쇄한다.
