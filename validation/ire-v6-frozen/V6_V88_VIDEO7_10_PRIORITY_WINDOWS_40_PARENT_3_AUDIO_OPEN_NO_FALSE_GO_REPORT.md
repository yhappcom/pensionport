## 실제 처리와 검증 경계

1. 원본 ZIP의 SHA-256과 #7 SRT의 SHA-256을 고정해 재검증하고 V33 분할을 재실행했다. V84~V87 비공개 ZIP의 SHA-256을 고정해 기존 #7 발화 69개의 원문·발화 ID·구간·원본 해시를 다시 확인했다.
2. V86의 **269개 창 전수 위험 선별 데이터**에서 앞선 V84~V87이 직접 검토하지 않은 창을 선정했다. 선정한 10개 창은 `W00093`, `W00110`, `W00140`, `W00143`, `W00151`, `W00162`, `W00174`, `W00226`, `W00238`, `W00239`이다. **10개 창을 완전 의미 분석했다고 인증하지 않으며**, 각 창에서 4개씩 총 40개 원본 후보 발화를 직접 읽고 문맥·화자 의도·적용 위험을 검토했다.
3. V84~V87과 **내부 중복 0건**. #7의 독립 발화 ID로 추적되는 **잠정 검토 기록은 69→109건**, 일부 부모 발화의 직접 검토 기록이 존재하는 창 **31→41개**, 해당 기록이 없는 창 **238→228개**다. 이 수치는 새 V88 계보의 범위이지 V75 정식 승인 및 전수 의미 재현율이 아니다.
4. V87의 `NEEDS_AUDIO` **3개는 동일 원문·원장 키로 미해결 상태를 유지**했다. 실제 음성자료 없이 자막의 숫자·고유명사를 자동 확정하지 않는다. 기존 V75 사적 원장 ID 목록과 역사적 V40 원본 이벤트 SQLite는 이번에도 복구/확정되지 않았다.

## 소프트웨어·증빙 검증

- 신규 **53개 합성 unittest** 일반·`python -O` 실행 모두 PASS. GitHub 전용 CI에서는 이 합성시험만 수행하며 비공개 원본 재생은 수행하지 않는다.
- 원본과 기존 4개 비공개 ZIP 실물에 대한 검증은 **소유자 비공개 재현 실행**으로 별도 수행했다.
- JSON(40개 발화·10개 창·3개 미해결), SQLite(10+40+3=**53개 신규 이벤트**), ZIP을 세 디렉터리에서 독립 생성해 SHA-256 **바이트 단위 동일** 확인. ZIP은 원본 SRT를 포함하지 않으며, 재현하려면 원본과 이전 버전 ZIP을 별도로 보유해야 한다.
- SHA-only 공개 영수증은 원본 아카이브, 기존 V84~V87 계보, 비공개 JSON/SQLite/ZIP의 검증 지문만 담고 원문·상세 ChatGPT 주석은 담지 않는다.
