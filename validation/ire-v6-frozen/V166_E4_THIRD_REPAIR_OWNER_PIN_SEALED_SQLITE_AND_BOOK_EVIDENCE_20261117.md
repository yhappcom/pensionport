# V166 E4 세 번째 개선 — 외부 키 봉인 승인 원장과 실제 B0001 책 원전 분리

**기준: 2026-11-17 KST. 사용자 확정 E4 합격 기준: 적법한 승인 입력 통과, 부적합 입력 차단.**

**최종 상태: E4 FAIL (안전성·원전 검증 상당 부분 개선), E1~E3 PASS 유지, E5~E7 NOT_RUN, 전체 엔진 NO-GO.**

## 1. E4 보호 객체 우회를 정식 승인 지식에서 차단: 외부 HMAC + 소유자 확인 해시

지난 E4 실패 사례는 **같은 SQLite 파일을 일반 V126 `PrivateKnowledgeStore`로 열어 E4 없이 연구후보를 쓸 수 있었다**는 점이다. Python 객체 수준 SQL authorizer만으로는 별도 DB 연결까지 물리적으로 차단할 수 없다.

새 `v166_e4_sealed_knowledge.py`의 `E4SealedKnowledgeStore`는 다음을 수행한다.

- 모든 자식 구간에 대해 **동일 실행 내 V123 최종 승인 + E4 공식 출처 확인**을 수행한 후 실제 V128 부모 발행이 성공해야 HMAC-SHA256 승인 영수증을 발급한다.
- SQLite `knowledge`, `events`, `parent_publications`의 **전체 논리 행과 V126 이벤트 체인 및 V128 부모 증명**을 대조하고, 모든 E4 자식 승인 해시와 부모 검토 체크포인트 헤드를 함께 봉인한다.
- 서명키는 **SQLite 외부에서 제공하는 최소 32바이트의 별도 비밀키**. CI에는 분명하게 표시된 **합성 시험키만** 사용한다. 운영 비밀키를 GitHub/SQLite에 보관하지 않는다.
- 소유자가 **DB와 별도로 보유하는 최신 봉인 SHA-256**을 제시하지 않으면 승인된 지식으로 인정하지 않는다. 과거 봉인·잘못된 키·변조된 승인 원장·데이터 행 수정이 발견되면 **전량 거부**한다.
- 승인 범위에서 벗어난 쓰기와 원래 V126의 제한 없는 `evidence_for_question`를 E4 인증 경로에서 거부한다.
- E4 공식 `run_e4_guarded_parent`는 이제 **반드시 봉인형 E4 저장소**를 요구한다. 이전 `E4GuardedKnowledgeStore`만 가지고는 정식 E4 발행을 수행하지 못한다.

**실측:** `test_v166_e4_sealed_knowledge.py` 11개 회귀 PASS: 정확한 봉인과 외부 pin 검증, 동일 파일에 일반 SQLite 연결을 사용한 무단 수정 후 인증 거부, E4 없는 레거시 V126 발행 파일의 인증 거부, 잘못된 키/외부 pin/훼손 봉인/이전 pin 누락/원시 V126 조회 차단, 합성 부모 검토 위조 차단. 기존 E4 직접 진입점 검증에 **비봉인 보호 객체 거부** 추가.

**정확한 제한:** 다른 SQLite 연결을 통한 **파일 쓰기 자체는 여전히 가능**하지만, HMAC+소유자 외부 pin 검증을 통과하지 못하므로 **E4 인증 지식으로 소비하지 못한다**. 애플리케이션이 E4 인증 저장소를 거치지 않고 구 V126 결과를 직접 금융 자문으로 사용하면 위험이 남는다. 롤백 저항성은 소유자가 **독립된 최신 pin을 지속 보관**할 때만 성립한다. 운영 비밀키/실제 사용자 외부 pin의 배치·보관 및 강제 조회 정책은 아직 미완료이다. SQLite COMMIT 직후 인증 파일을 기록하기 전에 장애가 발생하면 **DB는 기록되더라도 봉인이 없어 E4 승인 사용을 차단**하도록 설계했다.

## 2. 실제 영상 #1 B0001 책 서지 주장에 적합한 별도 승인 출처 경로

서지정보(책 제목·저자·ISBN)는 금융법/국세청 시행일과 같은 규범적 효력 계약으로 승인할 수 없다. 실제 B0001에서는 저서명을 소개하는 원자가 금융 관련 고위험 표시를 가졌으므로 **종류 분리**가 필요하다.

- 새 `v166_e4_video_book_source_custody.py`: 실제 영상 자막 cue·원자 SHA·V123 기존 처분·원문 직접 인용·ChatGPT 검문 메모를 원서 출판사 증빙과 연결한다.
- **C00002**: 책 제목·저자 소개. Wiley는 `The Dhandho Investor` / `Mohnish Pabrai`를 확인하고 국내 서지정보는 한국어 `투자를 어떻게 할 것인가` / `모니시 파브라이`를 확인한다. 단 원본 SRT의 이름 음역에는 차이가 있고 오디오 원본을 검증하지 못했다. **원래 V123 `OPEN`은 그대로**.
- **C00006**: 영어 책 제목의 음역 소개. 원서 출판사 데이터로 교차확인할 수 있고 기존 V123 `ACCEPT_FOR_RESEARCH` 상태를 **기존대로 유지**. 이것은 출판사에 의한 서지지원이지 별도 신규 E4 금융진실 승인 아님.
- 검증 함수는 원전 서지와 원문 인용을 대조하되 V123 `OPEN`을 `ACCEPT`로 변경하는 어떤 권한도 없다. 투자 성과 보장, 버핏의 초기 수익률, 기타 역사적 해석, 현재 금융법, 개별 투자자문 승인도 없다.
- **실제 비공개 원본을 직접 재대조한 2원자 출처 보존 영수증 SHA-256:** `408e6a56cad62d2a7fad62e678342b0a4e70425b178f5e74b7de80cae67eae52`. 검사 입력: 1,481 cue 원본 SHA-256 `638fefee007aa9122e68717b922194410ebbd7913a619bb9354f09af14468a0d`; V164 원자·V123 기존 처분의 실제 동일 ID/출처 cue 비교. **비공개 파일은 GitHub에 올리지 않았다.**
- `test_v166_e4_video_book_source_custody.py` 8개 합성 시험 PASS: 승인 후보 문헌 귀속, OPEN 유지, 가짜 인용·출판사 원문 해시 변조·없는 책·오디오 허위 인증·REJECT 자동승격·검토노트 SHA 위조 차단.
- 1차 출판사 Wiley 실물 HTTPS 검증: https://github.com/yhappcom/pensionport/actions/runs/44040578048 — 원서 원문 268,997 bytes, SHA-256 `194091165060cf91580a62597849a35e6a7d4e72d6544f039f795e1629b811d1`. 국내 서지: https://www.yes24.com/product/goods/61941283 (제3자 서지 메타데이터, 출판사 1차 증명 아님).
- 이 본건은 **private owner 로컬에서 원문·원자·Wiley 기존 보관 원전 직접 검사**했으며, 공개 GitHub의 신형 `assess_book_citation_against_primary`를 실제 사용자 비공개 패킷에 직접 import한 시험과 **구분**한다. GitHub 신형 계약 시험은 합성 사례다.

## 3. 재실행 및 공식 합격 기준

- [최종 E4 통합 CI](https://github.com/yhappcom/pensionport/actions/runs/44047834586) — E1~E4 순차 원장과 신규 봉인형 E4 통합을 포함한 **9개 jobs 모두 success**. 성공한 테스트는 **합성 긍정·부정 및 코드 보호조건**, 실제 금융주장의 적법성 판정이 아니다.
- 원본 B0001은 여전히 기존 final review에서 **C00002·C00009·C00010 등 금융/서지 원전 3건 OPEN**, source-only 5건 격리 후 7 ACCEPT 후보 / 3 OPEN / 6 격리. 부모 새 지식 발행 **0**.
- **E4 FAIL 사유:**
  1. 실제 영상 #1 B0001의 3개 미확정 원자와 고위험 의견불일치/원음 제약을 해결한 뒤, **하나의 실물 승인 입력이 E4→E3→V128 정상 저장을 완결한 증명 없음**.
  2. 금융법·시행일의 일치와 정확한 원문 인용 외 **법령 의역·조건·예외의 ChatGPT 의미 동등성 검문**이 여전히 미완성.
  3. 봉인형 운영 인증은 코드/CI로 입증했지만 실제 소유자의 **운영 서명키·외부 최신 pin 저장 및 인증 조회 진입점 고정**이 아직 없어 모든 정식 사용 경로의 법적 승인 강제를 인증하지 못함.

## 4. 순차 상태/불변

**E1 PASS · E2 PASS · E3 PASS · E4 FAIL (현 단계) · E5/E6/E7 NOT_RUN**.  
다음 명령도 **E4**의 남은 원전·동등성·운영 승인 강제 과제부터 다시 수행한다. 사용자 요청의 "13구간 실제 모두 승인해야만 원자적 지식 저장"인 E5를 앞당겨 실행하지 않는다.

기존 `main`, 동결 `V123`, `V126/V127/V128`, 실제 사용자 원본 SRT·기존 SQLite, 포트폴리오 미변경. GitHub 검증 브랜치와 draft PR만 변경.
