# V172 — 엔진 종단간 구간 순회 복구 / 검증 보고서

2026-11-19. 사용자 요청에 따라 기존 원자 의견의 재판정을 중단하고, `yhappcom/pensionport` V171→V166 동결 엔진의 **실행 제어 장애**를 우선 해결한다.

## 발견한 근본적 문제

- 기존 `v128_host_continuous_video.run_all_video_scopes_in_chat`는 처음 V123 HOLD 또는 REJECT를 만나면 즉시 리턴한다. `v166_e4_primary_approval_gate.run_e4_guarded_parent`도 처음 E4 공식 출처 HOLD에서 중단한다. 결과적으로 원래 영상 13개 구간 중 뒤쪽 12개가 해당 호출에서 전혀 검사되지 않을 수 있다.
- 코드·CI의 기존 PASS는 E1~E3 전송·구조 검증과 합성 V123/E4가 주이고, 실제 영상의 전 구간 종결을 의미하지 않는다. Python은 자체적으로 현재 ChatGPT 모델을 호출할 수 없다. 별도 API를 쓰지 않는 조건에서는 **현재 채팅이 실제 판정 입력을 공급해야** 한다.

## 실질 구현

`v172_full_video_engine.run_exhaustive_full_video`:

1. 원본 상위 체크포인트의 전체 자식 구간 수 및 목록과 사용자가 지정한 **완전 구간수**를 검사하여, 2/13개만 넘기는 부분 실행을 차단한다. 현재 1번 영상 운영 기준은 `expected_scope_count=13`; 합성 통합 테스트는 2개 구간이다.
2. 모든 구간을 우선 순회하여 개별 원본·호스트·ChatGPT V123 검토와 E4 출처 검문을 **기존 동결 E4 `assess_e4_primary_authority_gate`로 실제 실행**한다. 첫 번째 구간 HOLD 또는 예외라도 다음 구간으로 진행하고 모든 구간별 실패 이유를 집계한다. 민감정보가 들어 있는 예외 메시지는 반환하지 않는다.
3. 하나라도 미승인일 때는 V126 지식 SQLite·V128 원자 저장/발행을 호출하지 않고, 전체 구간별 `HOLD` 진단 결과를 낸다. 시점·법령·원음·개인적합성에 대한 증거를 자동 생성하지 않는다.
4. **전 구간 E4 PASS**일 때만 기존 E4 sealed publisher `run_e4_guarded_parent`를 재사용하여 공식 HTTPS 본문을 다시 검증하고, 동결 E3→V123→V128의 전체 영상 관계·경계·부모 승인까지 수행한다. HMAC 서명 및 외부 소유자 PIN을 갖춘 유일한 연구 지식 저장 경로를 그대로 이용한다. 직접 SQL로 자동 저장하는 새 우회는 없다.
5. 같은 채팅에서 원자별 의견을 다시 생성하지 않고 원본 고정된 호스트 판정 패킷을 재생한다. 합성 테스트 외 실제 ChatGPT 판단 생성/호출은 **미연결**, 엔진 내 API 없음.

## 증명 범위

- 테스트: 합성 자막 2구간·동결 V123/E4/부모 SQLite를 사용하는 **실제 실행기** 12개 통합 회귀시험, 기존 공식 E4·E3·V128 기능 회귀. 실패 주입: 첫/마지막/모든 구간 근거 누락, V123 OPEN, 잘못된 출처, 호스트 부재, 13구간 census 불일치, 부모 검토 부재, 경계 검토 누락, 모델 콜백 예외. 성공 경로는 E4 HMAC 서명·외부 PIN과 실제 원자적 DB 저장까지 검증.
- 기존 V166 PRIVATE 최신 13개 구간과 193 OPEN 판정의 실제 바이트·호스트 store는 이 실험에 제공되지 않았다. **실원본 완전 종단간 PASS 미입증**.
- 최종 상태: 엔진의 *첫 HOLD 조기 종료* 제거 및 안전한 전체 구간 검문 경로 구현. 소프트웨어 성공과 실제 영상 연구 승인 성과는 별개. E4 실제 영상 FAIL, 최신 OPEN 193, 신규 승인 지식 0. E5 실원본 발행 차단.
- 동결 V123/V126/V128, 기존 데이터, `main`은 변경하지 않았다. PR은 draft 유지.
