# V193 — E3 필수 **실제 사용자 2턴** 운영 계약 및 허위 검증 완료 방지

> **2026-11-20 · 최신 E3 운영 규칙 (V3 한 턴 연구, V177 프로세스 재개, V183 이후 2차 검토 배치보다 우선)**  
> 현재 시점: **E3 HOLD · V123/E4 NOT RUN · E5=0**. 연구·검토용 코드가 합성 CI를 통과해도 이 상태는 자동으로 변경되지 않는다.

## 1. 변경하지 않는 사용자 합의

**반드시 별개의 두 사용자 명령/응답 교환을 사용한다.**

| 단계 | 사용자의 대화 명령 | 엔진·ChatGPT의 역할 | 허용 결과 |
|---|---|---|---|
| **턴 1: 연구 실행** | “대상 영상 원본을 전부 분석하고 검증 대기 자료를 작성해 주세요.” | ChatGPT와 엔진이 원본·부모 발화·원자·화자·조건·예외·숫자·미확정 금융 근거를 분석하고 기존 지식과 비교. 원본 SHA와 1차 결과 head를 **비공개 동결**. | **잠정 연구/보류/격리 후보**, 고정 체크포인트, 미완료 작업. **E3 최종 의미 승인 불가**. |
| **턴 2: 최종 의미 검증** | 사용자가 **새 대화 메시지로** “앞서 동결한 연구를 원본·근거와 대조해 E3 최종 검증해 주세요.” | 이전 턴의 *실제* 소유자 원본·검증 대기 결과를 복구, 해시·자막·원자·조건·예외·시점·공식 근거 대조, 누락·왜곡·재판정·격리 및 E3 품질 검사. | 근거를 갖춘 **E3 승인/보류/격리 제안과 검증 영수증**. 품질 기준 미달·증거 부족이면 **HOLD**. E4/E5는 별도 관문. |

1턴에서 분석 구간이 여러 개이더라도 모두 **동일한 턴 1**이다. 턴 2에서 수십 개 2차 검토 배치를 실행해도 모두 **동일한 턴 2**다. 새 Python 프로세스, 리셋/재개, SQLite 추가, PR 커밋, 다른 모듈, source-only 패킷, **“1차/2차”라는 레이블**은 **별개의 사용자 대화 턴이 아니다**.

**턴 2는 턴 1 결과가 완전히 동결된 이후에 다른 사용자 메시지로 시작해야 한다.** 원본을 분할해 1턴에는 자막 1–125, 2턴에는 126–250을 분석하는 방식은 **2턴에 걸친 연구 연속성 검증**일 뿐, 합의한 **연구 1턴 → 최종 검증 1턴**의 실증이 아니다.

## 2. 검증과 이관의 강제 조건

- 턴 1 완료 증거: 사용자 명령의 실제 구분, 원본 SRT SHA-256, 원본 전체 범위, 연구 결과·추가 근거·OPEN과 원장 head, 서명 없는 자체 문자열이 아닌 **원본과 대조한 비공개 체크포인트**, 다음 검증에 넘길 범위. 턴 1에서 결과를 바꾸거나 지식 승인/발행 금지.
- 턴 2 시작 증거: **별도의 사용자 메시지**를 직접 관찰하고 두 번째 지시가 *새 연구 실행*이 아니라 *동결된 결과의 최종 의미 검증*임을 확인. 같은 원본 SHA, 턴 1 원장 head, 원본/판정 비교 출처 및 새 판정 head를 연결. 중간에 연구 결과 변경 시 턴 2 검증 무효화/다시 동결.
- 반드시 ChatGPT가 **연구의 최종 의미 검증 관문**을 담당한다. 독립적인 공식 금융 근거·시점 적용 검증과 원자 정답 평가 기준이 만족되지 않으면 ChatGPT도 **HOLD**해야 한다. 2턴 사용 자체가 의미 정확도나 정답셋 독립성을 입증하지는 않는다.
- **HOST가 검증한 메시지 ID/순서 등의 메타데이터가 노출되지 않는 환경에서는 도구가 사용자 턴을 암호학적으로 입증할 수 없다.** ChatGPT가 현재 대화에서 서로 다른 사용자 명령을 직접 관찰한 사실은 수동 영수증에 명확히 표시할 수 있으나 `host_verified`로 허위 인증해서는 안 된다. 자체 입력한 메시지 ref 두 개로 독립 ChatGPT 턴을 입증했다고 주장하지 않는다.
- E3 소프트웨어 실행 완료/자막 전수 검토/불일치 0/CI 통과/정답 참고셋 봉인은 **E3 정확성 승인과 다르다**. 독립 정답셋·고위험 누락·조건/예외·최신 금융 공식 근거 등 정해진 기준 미충족이면 **E3 HOLD / V123·E4 미실행 / E5=0**.
- 턴 2에서 오류를 발견하면 **실패한 턴 2의 E3 검문·오류 판정부터 개선**한다. 기존 턴 1·턴 2 원장과 HOLD/격리 상태를 그대로 보존한 채 원본 SHA·원자 SHA에 고정된 **append-only 교정 오버레이**로 의미 오류·중복·비원자·조건/예외 누락을 재검문하고, 필요한 공식 근거 부족과 구분한다. 수정할 수 없는 턴 1 원본 분석 자체의 구조적 결함이 입증되거나 E3 최종 승인을 위해 새 연구 산출물 생성이 필요한 경우에만 **새 턴 1 → 새 턴 2**를 수행한다. V195 실패한 최종 검증을 교정 턴이 소급하여 PASS로 만들지는 않는다. 운영 지침: [V196 실패 E3 검증 2턴 우선 교정](V196_E3_REPAIR_FAILED_SECOND_TURN_FIRST_KEEP_ORIGINALS_HOLD_20261120.md).
- 공개 GitHub/Actions에는 사용자 소유 원본 자막, 상세 의미 판정, SQLite와 개인 투자 자료를 업로드하지 않는다. 안전한 운영 문서·합성 테스트·해시만 저장한다. `main` 유지, 검증 PR Draft.

## 3. V179~V192 기록의 정정 (삭제/재작성 금지)

| 과거 성과 | 정확한 상태 | **금지되는 주장** |
|---|---|---|
| **V179** 사용자 대화 두 번에 걸쳐 원본 1–125와 126–250 분석 | **실제 턴 간 연구 이어달리기 검증** | “연구 턴 1 + 독립 최종 의미 검증 턴 2를 완료했다” |
| **V183** 별도 SQLite의 원본만 읽는 두 번째 분석 및 두 Python 프로세스 | **동일 ChatGPT 턴에서 실행된 비교/품질 진단** | “별도 실제 사용자 지시를 받은 E3 검증” |
| **V184~V192** 2차 250/250, 149건 원인 분류, 부모 발화·3중 69/71/72 대조, CMA 내부 참고셋 | **연구 엔진 개선·사후 비교·소프트웨어 검증 증거** | “검증용 분석 배치 수가 많으므로 합의한 2턴 합격 또는 독립 정답셋 PASS” |

따라서 과거의 `E3_TWO_TURN`, `second_pass`, `two_batch` 등의 **파일명은 증거가 아니다**. 모든 보고서·진행 요약은 실제 대화 턴을 확인하지 못했다면 `연구 지속/비교 실험`, `CHAT_TURNS_NOT_PROVEN`, `E3 HOLD`로 표시해야 한다. 소프트웨어 222/222 PASS는 별개 지표로만 남긴다.

## 4. 기계 판독용 방지 관문

`v193_e3_two_user_turn_contract.py`의 `validate_manual_turn_receipt`:

- 사용자 메시지 참조·각 메시지 내용 해시·역할을 분리하고, 턴 1의 **원본 SHA 및 동결 원장 head**가 턴 2의 대상과 일치해야 한다.
- 단일 사용자 명령을 `N`개 배치, 두 Python 프로세스 또는 두 보고서로 나누어도 별도 사용자 메시지의 *검증 증거*가 없으므로 2턴으로 인정하지 않는다.
- 동일한 사용자 문구(예: 두 번의 “진행해 주세요”)라도 서로 다른 실제 메시지라면 별개 턴일 수 있다. 메시지 내용 해시가 같다는 이유만으로 같은 턴이라고 판단하지 않는다. 반대로 서로 다른 `user_message_ref`가 입력되더라도 **호스트 제공 메시지 ID/순서를 독립 확인할 수 없어** `TWO_DISTINCT_USER_COMMANDS_CLAIMED_UNVERIFIED`로만 처리한다. 이 상태를 `TWO_USER_TURNS_PROVEN`이나 E3 PASS라고 변환하지 않는다.
- 구조/해시 불일치, 같은 사용자 메시지 재사용, 턴 1 미동결, 턴 2가 의미 검증이 아닌 연구 연속 실행, `e3_approved`/`v123_e4_approved`/`e5_published` 위조 시 실패로 닫는다.
- **합성 회귀시험은 정책 우회 차단만 검증**한다. 플랫폼 턴 구분 메타데이터가 도구에 노출되지 않으므로 새 검문 코드가 실제 2턴을 자동 인증해 주는 기능은 없다.

기계 판독 결과는 **운영 증빙**에 한정된다. ChatGPT의 실제 턴 2 검증 과정과 금융 사실 검증·정답셋 평가를 대체하지 않는다.

## 5. 다음 실제 수행 안내

1. 현재 V192의 연구 결과·원문 SHA·9개 비공개 원장을 **턴 1 연구 결과로 동결**하되, 과거 여러 턴의 개발·동일 턴 2차 검토를 신규 연구 1턴의 완주 증명으로 재해석하지 않는다. 다음 신규 영상 또는 기존 대상 1편을 대상으로 **턴 1을 새로 실행**해야 계약 실증이 깔끔하다.
2. 별도의 다음 사용자 메시지를 받고 **턴 2 최종 의미 검증**을 실제 수행한다. 채팅에서 관찰된 사용자 메시지 구분은 명시하되 호스트 인증이 없는 부분은 그대로 `UNVERIFIED`로 기록한다.
3. 오류가 남으면 `HOLD`와 수정 항목만 기록하고 승인·통합하지 않는다. 개선 후 재실행한다. E3 품질 기준이 충족되기 전까지 E4/E5를 진행하지 않는다.

**이 문서는 최신 운영 절차의 단일 참조점이다. 기존 역사적 실험 보고서는 삭제하지 않고 본 문서로 정정·해석한다.**

**보호 문서 범위:** `ire/README.md`는 과거 V3 연구 모드의 역사적 설명으로 변경하지 않는다. 최신 규칙의 진입점은 저장소 최상위 `README.md`와 이 V193 문서이며, 보호된 클린룸 정책을 완화하지 않고 우선순위를 관리한다.
