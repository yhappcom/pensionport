# V227 — E2 실물 재검토: 177 미해결 자막 계측 오류 분리, E3 68개 문맥 구조 통일, 2,278 원자쌍 선별 (2026-11-21)

**최종 의미 판정: E2 원본·연결·구조 검증 진행 및 수정 완료. 그러나 독립 정답셋 기반 의미 정확도는 미측정으로 HOLD.** 이 문서는 독립 평가의 가짜 100% 합격을 주장하지 않는다.

## 1. 이전 V226 평가의 구조적 오류

E2 보고서에서 'UNRESOLVED 자막 177개'를 곧바로 '미처리 주장 177개'처럼 취급하면 잘못된 병목이 발생한다. 동결 V6 `atomic_exchange`의 `UNRESOLVED`은 **대표 claim source_refs가 그 자막에 없다는 구조적 상태**다. 하나의 원자 주장은 여러 자막에 걸쳐 이어질 수 있어 수십 개 문장 조각이 대표 cue가 아니지만 정확히 context cue가 된다.

실제 사용자 비공개 원본 `LVE7XN_esTc` 250개 (원본 SHA-256 `e4aef32c007bc5e9f1ac6c3e18764ddc1b766e430893127cf98abe632c70301b`), V226 미승인 V6 원자 68개 (SHA `c8bec3354702cad0e85d4b111d2627ae2978806f3a4111c94a689d3b9e25baeb`)를 모두 다시 읽고 원자 source/context 관계를 계산했다.

|---|---:|---|

| 미승인 원자의 조건·전제·문맥 자막 | **154** | 기존 claim context_cue_indices와 1:1 참조 일치. **새 원자가 없다는 정답 판정 아님** |

**구조적 UNRESOLVED 177개의 실제 분포는 154 + 3 + 20 = 177**이고, cue14는 별도 `NO_ATOM` 경고다. 177개를 실제 놓친 금융 원자 177개로 보고 원자를 생성하면 가짜 주장 중복, 편향된 재현율, RunFail 문제가 커진다.

새 검토 우선 자막은 20개 담화 잠정 + 3개 시청각 문맥 + 1개 `NO_ATOM` = **24 cue**. 그러나 이것은 **검토를 먼저 해야 할 구간 수**일 뿐, 나머지 154개 context에서 내부 하위 원자가 더 없는지까지 입증한 것이 아니다. 원본 전체에서 숨은 원자 수, 진짜 FP/FN, 고위험 FN=0은 독립 정답 없이는 판정 불가.

## 2. 실제 후속 E3 런타임 자료형 불일치 수정

V226 E3 task 68개의 `source_context` 필드가 일관되지 않았다.

- 기존 65개: `source_context` = **list** of cue quote/SHA.
- 새 화면 발화 3개 `C00074,C00075,C00076`: `source_context` = **dict** with `source_refs` and `source_context_cue_indices`.

하나의 검토 처리 함수에서 원자별 `for ref in source_context`를 수행하면 세 원자에서 객체 키를 순회하게 돼 인용 검증·후속 조건 검사에서 예외/결손이 발생할 수 있는 **실제 인터페이스 결함**이다. 단순 유효한 해시만으로는 탐지되지 않았다.

V227은 **68개 E3 task 모두 동일한 원문 문맥 목록 구조**를 갖는 새로운 미승인 패킷을 생성한다. 기존 65개의 모든 심사 필드를 보존하고, 추가 3개는 원본 SRT의 cue 163~167, 212, 230~235를 원자 context/ref에 맞춰 **quote + SHA**로 재구성한다. 원래 원자·금융 위험·승인 조건 변경 없음. 패킷의 `e3_final_approved=false`, `e4_approved=false`, `e5_published=false` 유지.

실제 **68/68 E3 task** 형식 검증 PASS; 과거 dict 3개를 list로 정규화. 외부 정답과 금융근거가 없으므로 정식 E3 승인 단계는 여전히 HOLD.

## 4. 소프트웨어 근본 개선·RunFail 방지

공개 GitHub 검증 브랜치에 `validation/ire-v6-frozen/v227_e2_source_semantic_reconciliation.py`를 구현했다.

- 비공개 SRT 원본·68 native·250 census·이전 68 E3·새 cue ledger·새 E3·전수 pair ledger **7개 입력의 실제 바이트 SHA**와 동결 V6 `audit_host_atomic_exchange`를 재확인.
- `UNRESOLVED`을 뜻별로 나눠 계측: primary, context-linked, visual-context, provisional discourse, original `NO_ATOM`. **모든 250 cue의 원문 텍스트/해시/원자 ID와 재분류 상태가 일치해야 PASS**.
- 화면 의존 11 cue의 외부 비검증 상태, C00003 `NO_ATOM`, 그 외 개별 claim 문맥의 누락·오염을 **fail closed** 검출.
- E3 68 task에서 모든 `source_context`가 동일 list 구조이며 실제 source quote/SHA를 유지하도록 고정. 원자별 원래 질문·금융 위험·E3/E4/E5 차단은 원형 보존.
- 한 영상 원자 68개의 전수 쌍 **2,278행**을 결정론적으로 다시 계산하고, 28건의 수동 검토 이유와 남은 2,250건 미검증 상태를 분리.
- 잘못된 입력과 형식 누락은 `InvalidInput`으로 차단. 너무 큰 한 번의 원자 집합(512개 초과)은 무리하게 O(N²) 실행하지 않고 별도 샤드가 필요함을 명시적 실패로 반환.
- **원본 매니페스트 창 크기 불일치 방지:** 실제 V226 native 원장 window=20, 오래된 원본 계획 생성의 기본 window=120으로 호출하면 같은 SRT라도 manifest SHA가 바뀌어 V6 구조실패가 발생한다. `window_size`를 명시 입력으로 전달하고 값·원본 manifest를 검사함. 21 cue 합성 입력으로 20 vs 120 창 분할이 달라지는 회귀시험 추가.
- 공개 CI는 원본 금융 문장 없는 **합성 데이터 43개** 회귀시험만 실행. 실제 금융 원본 전체 재실행은 GitHub 밖 개인 컨테이너에서 완료. 이전 V226 633개에서 **총 676개**(현행 E2 605 + 이전 E2 53 + E1 18) CI에 연결. GitHub Actions [실행 44856993390](https://github.com/yhappcom/pensionport/actions/runs/44856993390)에서 **676/676 PASS**(현행 E2 605 + 이전 E2 53 + E1 18)를 확인했다. 이 결과는 합성입력 코드검사이며 독립 정답 기반 의미 정확도 인증은 아니다.
