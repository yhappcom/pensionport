# V170 — 원문 근거 요청과 ChatGPT 응답의 2단계 채팅 연계

**2026-11-19** · V169 검증 브랜치 기반 드래프트 변경. 기존 V166 E1–E3 PASS, E4 FAIL, E5–E7 NOT_RUN 상태는 이 작업으로 자동 갱신하지 않는다.

## 직접 고친 병목

V169에는 `evidence_retriever(task)`와 `chat_reviewer(request)`라는 Python **함수 콜백**이 반드시 존재해야 한다. 현재 채팅은 Python 함수 내부에서 재귀적으로 모델을 호출하는 실행기가 아니므로, 이전 구조는 '엔진 스스로 검색하고 모델 의미판정까지 완료'라는 사용자의 사용방식을 성취하지 못했다.

V170은 **현재 채팅이 판단을 공급하는 2단계 호스트 프로토콜**을 추가한다:

1. 비공개 V169 검토 원장 `ChatReviewJournal`를 열어 원본·원자·기존 검토 해시와 진행 헤드를 확인한다.
2. `prepare_chat_batch(...)`는 다음 OPEN 원자와 직접 자막 인용·조건·예외·숫자, 별도로 확보된 근거 원문 바이트 내부에 실제로 존재하는 인용문을 결합해 `request_sha256`, `batch_sha256` 고정 요청서를 반환한다.
3. **활성 채팅의 ChatGPT가** 반환된 원문을 읽고 `KEEP_OPEN`, `QUARANTINE_PROPOSAL`, `REJECT_PROPOSAL`, `CANDIDATE_NEEDS_NATIVE_REVIEW` 중 하나를 원자별로 *실제로 작성*해야 한다. 모델 생성·의미판정을 Python의 결정 규칙으로 위장하거나 '리뷰 완료=True'만 자동 채우면 실제 검증 성과가 아니다.
4. `ingest_chat_responses(...)`는 응답 전체 건수·순서·원자 ID·요청 해시·원문·검색 인용·중간 데이터 변경 여부를 재확인하고 **기존 V167 검증기와 V169 SQLite 원자적 배치**로만 기록한다. 미완료·무효 응답은 전체 롤백한다. 중단된 채팅은 다음 기동에서 안전하게 같은 원장으로 이어갈 수 있다.
5. 출력은 **미승인 연구 제안 영수증**이다. 최종 승인에는 V168의 독립된 2차 의미검토, 동결 V123 실제 호출, E4의 공식 원문 TLS 재수집·효력시점·범위·타입 검증이 별도로 필요하다. 13구간 모두 PASS 및 외부 PIN 없이는 V128 통합 지식을 발행할 수 없다.

## 검증 설계

신규 `test_v170_in_chat_review_bridge.py`에서 응답 전수 제출, 중복 채팅 전송, 재개 커서, 속임수 SHA, 출처 변경, 위조 모델 신원, 누락 원자, 2개 배치 중 1개 실패 후 전체 롤백, 근거 없는 ACCEPT 차단, E4 미발행을 포함한 15개 합성 검사를 수행한다. `test_v170_native_interop.py`는 별도로 3개 합성 시나리오에서 **동일 입력을 V170 → V169 → V168 → 동결 V123 → E4** 순서로 실제 재실행해, 승인 후보라도 E4 근거 누락 시 HOLD이며 실제 지식 발행은 없다는 점을 검문한다. 기존 V167–V169/native V123/E4 경계 회귀를 함께 실행한다.

## 한계/보안

- **ChatGPT가 Python을 통해 자동 소환된 것은 아니다.** 현재 대화가 위 2단계 요청·응답을 직접 실행해야 하며, 별도의 모델 API는 사용하지 않는다. 이 연결 방식은 도구를 호출하는 활성 채팅에서만 가능하고, 무인 백그라운드 실행이나 791편 전수 의미판정을 보장하지 않는다.
- JSON 내부의 `chat_reviewer_identity_attested=false`는 신뢰할 수 있는 신원 증명서가 존재하지 않는다는 올바른 상태다. 원문·검색 자료가 악의적인 명령을 포함할 수 있으므로 이를 지시로 수행하지 않는다.
- `_evidence_summary`가 검사하는 것은 `excerpt`가 bytes 내부에 실제 존재하는지뿐이다. URL만으로 공인 발행인·법령 시행일을 인증하지 않는다.
- 비공개 원본·개인 입력·SQLite·풀텍스트 검토 결과는 GitHub에 커밋하지 않는다.
- 이번 실행 환경에 최신 V166 비공개 최종 193 OPEN 원장이 발견되지 않았다. 과거 V162/164 혼합 242 OPEN를 최신으로 대체하거나 감소 지표로 인용하지 않는다.
- E4 FAIL / E5 NOT_RUN / 새 공식 승인·발행 지식 0은 유지한다.
