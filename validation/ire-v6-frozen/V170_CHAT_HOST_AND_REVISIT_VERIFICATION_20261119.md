# V170 — ChatGPT 직접 판정 수신 / 미해결 OPEN 재검토 경로

기준: 2026-11-19. 부모 V169 검증 브랜치에서만 작업. 동결 V123/V126/V127/V128, 보호 main, 비공개 원본/지식 데이터 변경 금지. E4 FAIL, E5–E7 NOT_RUN이며 13/13 승인이나 통합 지식 발행을 주장하지 않는다.

## 구조적 결함 및 수정

- **실행 경계:** V169에는 모델을 직접 호출할 수 있는 API가 없는 상태에서 Python `chat_reviewer` 함수를 요구하는 막힌 인터페이스가 있었다. `v170_in_chat_review_bridge.py`는 채팅 실행기가 한 턴 내에서 `prepare_chat_turn`으로 원본 cue, atom, 조건/예외, 검색 근거 요약과 정확한 request SHA를 읽고 *현재 ChatGPT가 직접* 의미 분석/반례 검토 결과를 작성하도록 하는 동기식 challenge-response 계약이다. 채팅 실행기가 답변을 다시 `commit_chat_turn`으로 넘겨주면 **기존 V167 검문과 V169 SQLite 원자적 저널**이 다시 확인한다. 테스트 콜백을 실제 모델 실행으로 가장하지 않는다.
- **미해결 OPEN 영구 봉쇄:** V169에서는 `KEEP_OPEN`을 단 한 번 처리하고 최초 cursor가 끝나면 더 이상 근거가 생긴 원자를 검토할 수 없었다. `v170_evidence_revisit.py`는 이전에 실제로 기록한 KEEP_OPEN만, *이전에 사용하지 않은 새로운 원본 근거 바이트 SHA*가 나왔을 때 다시 검토하도록 하고, 원문·원자·이전 검토 SHA를 유지한 별도 SQLite 해시 체인으로 누적한다. 사용했던 동일 증거는 다시 검토하며 완료 건수로 계산할 수 없다.
- **전 단계 결합:** 최초 검토 및 재검토의 최신 제안을 V168-compatible **미발행 제안 영수증**으로 내보낼 수 있다. 정식 V123 승인에는 별도 ChatGPT의 원자별 2차 검토 행·실제 바이트·원문 전체 전수대조가 필요하며, E4는 금융 근거 원전의 신뢰 발행기관·적용 범위·유효일을 독립 검증한다. 어떤 V170 함수도 승인 상태나 발행 DB를 변경할 수 없다.
- **오류 차단:** stale journal head, 누락된 답변, 뒤바뀐 청구 ID, 원문/증거 SHA 변조, 모델 신원 인증 허위 표기, 같은 증거의 반복 재심사, 채팅 중단, SQLite 쓰기 실패는 모두 부정 처리한다. SHA 체인은 파일을 마음대로 다시 쓸 수 있는 내부 관리자를 상대로 cryptographic owner attestation이 아니다.

## 아직 충족하지 못한 부분

- 채팅 환경이 Python 모듈을 호출하는 실운영 연결 및 그 호출 결과의 chat-origin 신원 증명은 제공되지 않는다. V170으로 함수 호출 계약은 만들어졌지만 ChatGPT 호출 엔진을 갖춘 것은 아니다.
- 최신 193 OPEN V166 원장은 이 실행 환경에서 확보되지 않아 실제 전수 판정/13 children PASS를 주장하지 않는다.
- 기존 prior knowledge 관계/공식 금융 원문 적용 가능성/독립 semantic gold/최종 V128 단일 원자적 E5 저장은 아직 미검증이다.
- `KEEP_OPEN` 재심사에는 **새 원본 근거**가 필요하므로 새 근거가 없다면 미해결 상태는 여전히 지속한다. 단순 반복/가짜 처리량 금지.
