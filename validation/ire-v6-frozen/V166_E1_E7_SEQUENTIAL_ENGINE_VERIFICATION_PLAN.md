## 2. 증명 규칙 및 각 단계별 반례

- **E1**: 실제 V6 원본/원자 출처 교환 → ChatGPT 검토 문서 → 공식 버전의 승인 토큰 → V126 격리 지식 저장 → V128 전체 발행까지 *동일한 소스·호스트 digest*의 실행 경로를 추적한다. 합성 허용 사례 최소 1개에서 **실제 신규 지식 저장**을 확인하고, 실제 승인 보류/증거 부재/유형별 source-only 입력이 별도 원인 없이 잘못 통과·차단되지 않는지 확인. 기존 V164 typed precheck가 V126/V128에 전달되지 않는 설계 결함부터 해결. E1은 '경로 존재'만 검증; 판단 자체의 정확도는 E2~E4에서 별도로 심사.
- **E2**: 원본 자막에 고정된 질문·의견·가설·객관 금융 사실 사례 및 조건·예외·반박·숫자를 정답 케이스로 사전 고정. 오분류·문맥 손실은 FAIL. 인용 해시가 같다는 사실만으로 의미 보존 인증 금지.
- **E3**: ChatGPT의 개별 원자 승인·보류·격리 상태와 이유를 계약에 반영. 판단 수정 시 구/신 판정과 근거가 추적돼야 하고, 미검토 건은 공개 불가.
- **E4**: 적법한 승인, 미검증 금융 주장, 위험 누락, 출처 위조, 의견을 사실로 둔갑시킨 사례를 모두 실행. 위조·보류를 승인하면 FAIL. 중복 위험 카운터는 실제 원문 검문과 별도 계측.
- **E5**: 실제 영상 #1의 **13개 자식이 모두 PASS**해야 V128이 원자적으로 새로운 승인 연구 지식을 저장. 12/13 PASS 시 SQLite 지식·이벤트·부모발행 증가 0. 합성 전구간 PASS와 실물 13/13 PASS 구분.
- **E6**: 같은 입력 재실행은 멱등; 임의 구간/근거/원자/해시 변조·중간 실패·SQLite 조작은 실패 폐쇄; 기존 승인 원장과 보호 브랜치 불변.
- **E7**: 실제 신규 저장된 지식 ID → 영상·cue·원자→원전/현행 금융법 적용 범위→답변 근거로 역추적; V165 사전 고정 18문항 평가를 통해 답변 오류·고위험 누락·개인별 무근거 자문을 판정. 연결 여부와 독립적인 정확도 인증은 분리.

## 3. 순차 실행 알고리즘

1. 최초 단계 `E1`만 `IN_PROGRESS`로 표시한다. 실행 전 commit SHA·원문/테스트 출처·기준선과 증명 방식을 기록한다.
2. 시험으로 결함이 확인되면 `FAIL`로 기록하고 원인·실제 재현 단계·수정 커밋을 남긴다. **같은 단계만** 수정하고 동일 반례로 재시험한다.
3. 요구한 모든 긍정·부정 시험 및 실제 기록이 충족된 경우에만 `PASS`로 확정한다. 이후 차례의 단계 **정확히 하나**를 `IN_PROGRESS`로 바꾼다.
4. 필요한 비공개 원본·실행기·공식 자료를 확보할 수 없다면 `BLOCKED`; 성과를 허위 추정하거나 다음 단계로 이동하지 않는다.
5. 각 단계는 코드/원본 SHA, 테스트 명령/CI run URL, 관찰값, 실패/수정 이력, 사용자 합격 기준 1:1 대조표를 포함한 `E*_EVIDENCE` 보고서로 검문한다.
6. 전체 E1~E7 PASS 이후에도 **독립 정밀도≥95%·재현율≥98%·고위험 FN=0**은 별도 독립 gold 없이는 인증하지 않는다.
