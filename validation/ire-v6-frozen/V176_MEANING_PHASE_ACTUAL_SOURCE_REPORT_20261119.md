## 새로 확인한 오케스트레이터 결함과 수정

1. 기존 V176 `prepare()`는 B0001의 의미 검토가 끝나면 문맥 재검토·원전 검색을 먼저 요구하여 **2번 과제(자막 전체 의미 분석)를 독립적으로 진행할 수 없었다.** `prepare(source_first_only=True)` 및 CLI `next-meaning`을 추가해 문맥 재검토·공식 원전 검색에 가로막히지 않고 B0002 이후 전체 원문 1차 의미 검토로 진행하게 했다. 정식 `prepare()`의 기존 E4 작업순서와 보류 정책은 변경하지 않았다.
2. 이미 저장한 원자의 문맥에 앞선 시점이나 조건이 빠질 경우 동결 V6는 실패했지만, V176은 기존 ASSERTION의 원자 수정 이벤트를 허용하지 않았다. `prepare_atom_repair()` 및 CLI `repair-atom`, `submit_context_revisit()`의 **원본 SHA·이전 이벤트 해시·원자 인용·숫자 출처 검사 후 별도 append-only 정정** 경로를 추가했다. 원래 판정과 SQLite 이전 이벤트를 보존하며 승인 권한은 없다.
3. `submit()`은 의미 분석 우선 작업의 `review_phase`를 검사하고 엔진이 동일 원본·원장 상태에서 발행한 정확한 challenge와만 일치할 때 받아들인다. 위조 challenge, 근거 없는 숫자, 비주장 발화의 임의 원자 정정은 차단한다.
4. **ChatGPT가 실제 검토 결과를 공급해야만** 제출 가능하다. Python 자체적으로 ChatGPT를 호출하거나 금융 진실을 자동 판정하지 않는다.
