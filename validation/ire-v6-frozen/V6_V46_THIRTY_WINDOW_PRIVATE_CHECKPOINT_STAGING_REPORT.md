## 작업 이유

V43(6창)·V44(8창)·V45(16창)의 실제 원본 의미 메모는 기존 8개 창의 정식 V39/V40 검문 완료 실적에 합산되지 않았다. 소스 SHA와 ChatGPT 자체 검토 메모 해시만 저장돼 있어 GitHub V39/V40 코드가 받는 입력으로 바꾸고, 원장에 연계될 수 있는지 실제 소유자 원본으로 점검했다.

## 비공개 원본·후보·의미 재현

`/mnt/data/1-100.zip`을 실제로 다시 열고, 첫 5편의 SRT 각각에 대해 **원본 파일 SHA·전체 cue 수·V33 발화분할 및 전체 누적 ID를 1번 cue부터 재계산**하였다. V43/V44/V45의 신규 30개 창의 **원문 창 SHA와 V33 후보 목록 SHA를 30/30** 재대조하고, 각 후보의 정확한 원문 인용 SHA·cue 구간·의미 메모 목록을 일대일로 대조했다.

## 새 사유지 원장 저장 및 검문

**별도 소유자 비공개 SQLite 데이터베이스**를 생성했다. 테이블 `v40_checkpoints`, `v40_window_ownership`과 `IRE_V6_V40_CHAT_SEMANTIC_CHECKPOINT_V1`의 원자적 해시 체인 구성요소를 **로컬에서 재구현**하여, 5개 영상별 최대 4창씩 총 **10회** 트랜잭션에 SHA-only 체크포인트 **10건/원본 창 소유권 30건**을 기록했다. 저장된 원장에는 원본 자막 문장, 사용자 개인발화, ChatGPT 의미 설명 텍스트가 없고 비공개 원본 SHA, 창 ID, V39 영수증 해시, 후보/메모 총수치만 있다.

**10회 동일 요청 재실행에서 10/10 idempotent**, 새 증빙 중복 원본 창 소유권 SQL UNIQUE 제약 차단, 변경된 저장값 해시 불일치 탐지, 중간 트랜잭션 실패 시 본문/창소유권 모두 롤백 확인했다. 비공개 SQLite SHA256: `25a013072614d8bc63f0b59a606e033e1b44b0ab9e3c886a2f6c6b3e345920e5` (32,768 bytes). 로컬 순수 해시 영수증 SHA256: `a9d70971e7091a5d7dcb7fd34d973779423873fe7ebdb5c7c7fb11d2345faed7`. 이 해시를 담은 **10개의 공개 안전 요약 영수증**을 저장했다.

**중요한 구현/정식검증 구분:** 실제 GitHub `ire/v6/host_semantic_custody_v39.py`와 `ire/v6/semantic_checkpoint_v40.py`를 컨테이너에서 직접 import해 실행한 것은 **아니다**. 이번에는 GitHub에서 확인한 검문 구조와 SQLite 해시 방식을 로컬에서 재구현해 비공개 데이터의 **별도 이관 대기 스테이징 DB**를 만든 것이다. 원래 V40에서 생성한 8개 창 DB 또한 이 실행 환경에 첨부되어 있지 않아, 이 30개 창을 이전 8개 창 원장에 같은 head로 이어 붙였다는 주장은 하지 않는다. 따라서 **정식 V39/V40 실행 완료 실적은 기존 8개 창**, 신규 30개 창은 **독립 재현·원장형 검증 대기**로 기재한다.

## 선행 연구 완료율은 보존, 금융 사실/지식 승인 무변경

- 원본 구조 재현 **130/130**, 발화별 ChatGPT 1차 의미분류 **38/130**.

- 신규 30개 창의 이번 **비공개 스테이징 DB 30/30**은 잠정 구조·원본 체인 검사 완료, **정식 V40 GitHub 코드 통과 = 0/30**.
